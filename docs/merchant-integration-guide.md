# Merchant Integration Guide

This guide provides the technical specifications for merchants integrating with the Payam Payment Gateway. It covers authentication, payment initiation, error handling, and webhooks.

## 1. Overview

The Payam API allows merchants to initiate mobile money payments (MTN and Orange) via a single unified interface.

### Integration Flow
1.  **Initiation**: Merchant backend calls `POST /v1/payments`.
2.  **Authentication**: Payam validates the Merchant's API Key.
3.  **Validation & Fraud**: Payam performs technical validation and fraud checks.
4.  **Routing**: Payam routes the request to the appropriate provider (MTN/Orange).
5.  **Status Notification**: Payam notifies the merchant via a Webhook when the transaction reaches a terminal state (Success/Failure).

---

## 2. Authentication

All API requests must be authenticated using an API Key provided during onboarding.

| Header | Description |
| :--- | :--- |
| `X-Api-Key` | Your unique merchant API Key. |

> **Security Note**: Never expose your API Key in frontend code (JavaScript). All calls to Payam should be made from your secure backend server.

---

## 3. Initiate Payment

**Endpoint**: `POST /v1/payments`  
**Content-Type**: `application/json`

### Request Payload

| Field | Type | Mandatory | Description |
| :--- | :--- | :---: | :--- |
| `msisdn` | String | Yes | The subscriber's phone number in E.164 format (e.g., `+237690000000`). |
| `amount` | Decimal | Yes | The amount to charge. Must be positive. |
| `currency` | String | Yes | ISO-4217 currency code. Only `XAF` is currently supported. |
| `idempotencyKey` | String | Yes | A unique string generated by the merchant to prevent duplicate charges on retries. Max 255 chars. |
| `externalReference`| String | No | Your internal order or transaction ID. This will be echoed back in webhooks. |
| `deviceFingerprint`| String | No | A fingerprint of the customer's device (e.g., from FingerprintJS) for fraud prevention. |

**Example Request**:
```json
{
  "msisdn": "+237690000000",
  "amount": 1500.00,
  "currency": "XAF",
  "idempotencyKey": "order-12345-uuid-random",
  "externalReference": "INV-2024-001",
  "deviceFingerprint": "browser-hash-xyz-789"
}
```

### Response Payload (202 Accepted)

On successful initiation, the API returns a `202 Accepted` status.

| Field | Type | Description |
| :--- | :--- | :--- |
| `transactionId` | String | Payam's internal unique ID for this transaction. |
| `status` | String | Initial status, usually `PROCESSING`. |
| `providerRef` | String | The reference returned by the mobile operator (MTN/Orange). |
| `feeAmount` | Decimal | The fee applied to this transaction by Payam. |
| `feeRuleId` | Long | The ID of the fee rule that was applied. |

**Example Response**:
```json
{
  "transactionId": "tx_abc_123",
  "status": "PROCESSING",
  "providerRef": "pay-token-xyz",
  "feeAmount": 15.00,
  "feeRuleId": 501
}
```

## 4. Error Handling

If a request fails, Payam returns an appropriate HTTP status code and an error object.

### Error Object Structure
```json
{
  "errorCode": "ERROR_NAME",
  "errorMessage": "Description of what went wrong"
}
```

### Standard Error Codes

| HTTP Status | Error Code | Meaning | Merchant Action |
| :--- | :--- | :--- | :--- |
| 401 | `UNAUTHORIZED` | Invalid or missing API Key. | Check your `X-Api-Key` header. |
| 422 | `UNKNOWN_MSISDN_PREFIX` | Phone number not recognized. | Validate the MSISDN format. |
| 422 | `SUBSCRIBER_INACTIVE` | User's mobile money account is closed/inactive. | Ask user to use another number. |
| 422 | `FRAUD_BLOCKED` | Request blocked by fraud engine. | Possible attack or high-risk transaction. |
| 502 | `PROVIDER_ERROR` | Mobile operator returned an error. | Retry later or contact support. |
| 503 | `PROVIDER_UNAVAILABLE` | Connection to operator is down (Circuit Open). | Switch to another provider if available. |

## 5. Webhooks (Status Notifications)

Payam sends a `POST` request to your pre-configured `webhookUrl` once the transaction is completed.

### Webhook Payload

| Field | Type | Description |
| :--- | :--- | :--- |
| `transactionId` | String | Payam's unique transaction ID. |
| `status` | String | Final status: `SUCCESS` or `FAILED`. |
| `eventType` | String | Detailed event name (e.g., `PROVIDER_SUCCESS`). |
| `timestamp` | String | ISO-8601 timestamp of the event. |
| `externalReference`| String | The reference you provided in the initiation request. |
| `feeAmount` | Decimal | The final fee amount applied. |

### Security (Signature Validation)
Every webhook includes an `X-Payam-Signature` header to ensure the request came from Payam.

**Header Format**: `X-Payam-Signature: sha256=<hex_hash>`

To validate:
1.  Compute the HMAC-SHA256 of the raw JSON request body using your **Webhook Secret**.
2.  Compare the resulting hex string with the signature in the header.

---

## 6. Best Practices

1.  **Idempotency**: Always use a unique `idempotencyKey` for every new payment attempt. If you retry a request due to a network timeout, use the *same* key to avoid double charging.
2.  **Fraud Prevention**: Send the `deviceFingerprint` if possible. This helps Payam protect you from coordinated attacks across different merchants.
3.  **Webhook Reliability**: Your webhook endpoint should return a `200 OK` as quickly as possible. Payam will retry failed webhook deliveries with exponential backoff.
