# Architecture

**Analysis Date:** 2026-03-06

## Pattern Overview

**Overall:** Full-stack monolith — Spring Boot 3.x backend serving a Quasar/Vue 3 SPA, packaged together via Maven. The frontend is built by `frontend-maven-plugin` and copied into `target/classes/static` so both tiers ship as a single JAR.

**Key Characteristics:**
- Backend uses a feature-module layout within a single Maven project (no microservices)
- Security is a first-class vertical module that cuts across the whole backend
- Frontend communicates exclusively via the same-origin REST API using cookie-based JWT auth
- Event-driven internal communication: email sending, audit, and session events flow through Spring's `ApplicationEventPublisher`
- Flyway manages all DB schema evolution; DDL is never auto-generated by Hibernate at runtime

## Layers

**REST / API Layer:**
- Purpose: Accepts HTTP requests, validates input, returns typed response objects
- Location: `src/main/java/com/softropic/payam/security/api/`
- Contains: `@RestController` classes (`AccountResource`, `ProfileResource`), a Facade service (`AccountManagementFacade`), DTO record types, `@RateLimited` AOP annotation
- Depends on: Service layer, MapStruct mappers, common message types
- Used by: Frontend SPA, external HTTP clients

**Service Layer:**
- Purpose: Business logic, transaction management, domain orchestration
- Location: `src/main/java/com/softropic/payam/security/service/`
- Contains: `UserService`, `UserRegistrationService`, `UserProfileService`, `PasswordResetService`, `LoginInfoService`, `CustomerService`
- Depends on: Repository layer, domain objects, event publisher, common utilities
- Used by: API layer, security filter chain

**Domain Layer:**
- Purpose: JPA entities carrying business state and business methods
- Location: `src/main/java/com/softropic/payam/security/domain/`
- Contains: `User`, `Customer`, `Authority`, `Address`, `PersistentToken`, `Challenge`, `LoginInfo`
- Depends on: `common/persistence/BaseEntity` and `AbstractAuditingEntity` (base classes)
- Used by: Service layer, repositories

**Repository Layer:**
- Purpose: Data access via Spring Data JPA
- Location: `src/main/java/com/softropic/payam/security/repository/`
- Contains: `UserRepository`, `AuthorityRepository`, `LoginInfoRepository`, `PersistentTokenRepository`
- Depends on: Domain entities, JPA
- Used by: Service layer

**Common / Shared Layer:**
- Purpose: Cross-cutting infrastructure shared by all feature modules
- Location: `src/main/java/com/softropic/payam/common/`
- Contains: `BaseEntity`, `AbstractAuditingEntity`, `AbstractClient` (HTTP outbound), exception hierarchy, validation annotations, utility classes, message response types (`Success`, `Failure`, `Response`), thread-pool MDC propagation
- Depends on: Nothing in the application
- Used by: All other layers

**Email Module:**
- Purpose: Isolated feature module for email delivery
- Location: `src/main/java/com/softropic/payam/email/`
- Contains: `MailService` (Thymeleaf + JavaMail), `MailManager`, `MailSenderProvider` (round-robin provider), persistence for email tracking, `Envelope` event record
- Depends on: `common`, Spring Mail, Thymeleaf
- Used by: Security service layer via Spring events

**Security Infrastructure:**
- Purpose: Authentication, authorization, JWT lifecycle, audit, fraud detection
- Location: `src/main/java/com/softropic/payam/security/`
- Contains: Filter chain (`SecurityConfiguration`), JWT filters, managers, listeners, secret service, audit filter, rate-limiting AOP
- Depends on: `common`, Spring Security, JJWT, Bucket4j
- Used by: All inbound HTTP requests

**Frontend Application:**
- Purpose: Quasar/Vue 3 SPA
- Location: `src/frontend/src/`
- Contains: Pages (`pages/`), layouts (`layouts/`), API client modules (`api/`), Pinia stores (`stores/`), composables (`composables/`), Vue Router (`router/`), boot files (`boot/`)
- Depends on: Backend REST API (same-origin, cookie auth)
- Used by: End users via browser

## Data Flow

**User Registration:**
1. `POST /v1/account/register` → `AccountResource.registerAccount()`
2. `AccountManagementFacade.registerAccount()` applies `@RateLimited` AOP check
3. Facade delegates to `UserRegistrationService.createUser()` for persistence
4. Facade selects `EmailRegistrationStrategy` or `SmsRegistrationStrategy` (Strategy pattern)
5. Strategy publishes an `Envelope` event via `ApplicationEventPublisher`
6. `SendMailListener` handles the event, calls `MailManager` → `MailService`
7. `MailService` renders Thymeleaf template and sends via `MailSenderProvider`

**Login / JWT Auth:**
1. `POST /authenticate` is intercepted by `JWTAuthenticationFilter` (before `UsernamePasswordAuthenticationFilter`)
2. Filter delegates to `FraudAwareAuthenticationManager`, which wraps `DaoAuthProvider` and `LoginDecisionManager`
3. On success, `LoginTokenManager.createLoginToken()` writes a JWT cookie to the response
4. Subsequent requests pass through `JWTAuthorizationFilter`, which validates the JWT cookie and loads the `SecurityContext`
5. 2FA: if OTP enabled, `JWTAuthenticationFilter` sets a pending state and `SecondFactorLoginFilter` handles `/otp` verification
6. `SessionRefreshFilter` intercepts `/refresh` to renew token TTL without re-authentication

**Email Sending (Event-Driven):**
1. Any service publishes `Envelope` event via `ApplicationEventPublisher`
2. `SendMailListener` (a Spring `@EventListener`) receives the `Envelope`
3. `MailManager` persists the email request, then invokes `MailService`
4. `MailService` resolves the Thymeleaf template by enum name and sends via SMTP

**State Management (Frontend):**
- Pinia store initialized in `src/frontend/src/stores/index.js`
- Session state managed by `src/frontend/src/plugins/sessionManager.js` and `useSession` composable
- Axios instance in `src/frontend/src/boot/axios.js` injects `Accept-Language` header, tracks pending requests, and redirects to `/login` on 401

## Key Abstractions

**BaseEntity / AbstractAuditingEntity:**
- Purpose: Universal entity root with TSID-based Long PK, Hibernate Envers auditing, createdBy/lastModifiedBy via Spring Data auditing, `requestId`, `sessionId`, and `EntityStatus`
- Examples: `src/main/java/com/softropic/payam/common/persistence/BaseEntity.java`, `src/main/java/com/softropic/payam/common/persistence/AbstractAuditingEntity.java`
- Pattern: All JPA entities must extend `BaseEntity`; entities requiring audit trail extend `AbstractAuditingEntity`

**ApplicationException hierarchy:**
- Purpose: Typed exception tree with auto-generated `supportId` (Sqids-encoded UUID), `ErrorCode`, and structured `logContext` map for correlation
- Examples: `src/main/java/com/softropic/payam/common/exception/ApplicationException.java`, `src/main/java/com/softropic/payam/security/exposed/exception/SecException.java`
- Pattern: All business errors throw a subclass of `ApplicationException`; response body includes the `supportId` as `helpCode` for support correlation

**Success / Failure response types:**
- Purpose: Uniform JSON response envelope: `Success` (helpCode, i18n key, message, extra data) and `Failure` (mirrors `Success` for errors)
- Examples: `src/main/java/com/softropic/payam/common/message/Success.java`, `src/main/java/com/softropic/payam/common/message/Failure.java`
- Pattern: Controllers return `Success` directly; error responses are handled by exception handlers that produce `Failure`

**AbstractClient:**
- Purpose: Base class for all outbound HTTP clients (e.g., MTN MoMo); encapsulates `RestTemplate`, request interceptors, and health-check endpoint
- Examples: `src/main/java/com/softropic/payam/common/client/AbstractClient.java`
- Pattern: Create a concrete client by extending `AbstractClient` and injecting host/heartbeatPath from config

**LoginTokenManager (interface):**
- Purpose: Single contract for the entire JWT cookie lifecycle — create, renew, refresh, delete, extract, validate
- Examples: `src/main/java/com/softropic/payam/security/common/service/LoginTokenManager.java`
- Pattern: Injected into all security filters; implementation lives in `security/common/`

**@RateLimited AOP annotation:**
- Purpose: Declarative per-IP rate limiting using Bucket4j; applied on facade methods
- Examples: `src/main/java/com/softropic/payam/security/api/ratelimit/RateLimited.java`
- Pattern: Annotate public service/facade methods with `@RateLimited(key = "...", capacity = N, duration = M)`

**RegistrationNotificationStrategy (Strategy pattern):**
- Purpose: Decouples registration notification channel (email vs SMS) from business logic
- Examples: `src/main/java/com/softropic/payam/security/api/registration/EmailRegistrationStrategy.java`, `SmsRegistrationStrategy.java`
- Pattern: `AccountManagementFacade` selects the strategy at runtime based on `LoginIdType`

## Entry Points

**Backend Application Bootstrap:**
- Location: `src/main/java/com/softropic/payam/PayamApplication.java`
- Triggers: `java -jar` or Maven `spring-boot:run`
- Responsibilities: Bootstraps Spring context; `@EnableRetry` activates Spring Retry

**HTTP Entry — Public REST:**
- Location: `src/main/java/com/softropic/payam/security/api/AccountResource.java` (`/v1/account/**`)
- Triggers: Unauthenticated HTTP requests (registration, activation, password reset, ping)
- Responsibilities: Input validation, delegates to `AccountManagementFacade`

**HTTP Entry — Authenticated REST:**
- Location: `src/main/java/com/softropic/payam/security/api/ProfileResource.java` (`/v1/**`, `/api/**`)
- Triggers: Authenticated HTTP requests
- Responsibilities: Profile and account management; guarded by `JWTAuthorizationFilter`

**Security Filter Chain:**
- Location: `src/main/java/com/softropic/payam/security/config/SecurityConfiguration.java`
- Triggers: Every inbound HTTP request
- Responsibilities: CORS, CSRF disable, authentication/authorization, cookie management, logging, 2FA, session refresh

**Frontend SPA Entry:**
- Location: `src/frontend/src/App.vue`
- Triggers: Browser load of `index.html` (served from `target/classes/static/`)
- Responsibilities: Mounts Vue router; boot plugins run (axios fingerprint setup, i18n)

## Error Handling

**Strategy:** Exception-to-HTTP translation via Spring `@ControllerAdvice` (not shown explicitly but referenced by `HandlerExceptionResolver` injected into security filters). Security filters delegate exception handling to `HandlerExceptionResolver` to keep error format consistent.

**Patterns:**
- All business exceptions extend `ApplicationException` with a unique `supportId`
- Security exceptions extend `SecException` with a `SecurityError` enum code
- `401 Unauthorized` → `AuthenticationExceptionHandler`
- `403 Forbidden` → `ApplicationAccessDeniedHandler`
- Frontend axios interceptor handles 401/403/5xx with user-facing messages and session cleanup

## Cross-Cutting Concerns

**Logging:** Logback with Logstash JSON encoder (`net.logstash.logback`). `LoggingFilter` logs request/response payloads (excluding static assets), sanitized via `BodySanitizer`. MDC propagation across thread pools via `MdcDecorator` and `MdcWrapper`. Tomcat access log writes to `/usr/local/var/ledger/payam_access.ledger`.

**Validation:** Jakarta Bean Validation on all DTOs (`@Valid`). Custom annotation validators: `@CamPhone`, `@CamMobile` (Cameroonian phone numbers), `@LangIso2`, `@Name`, `@PhoneNumber`, `@LocalDateWindow`. Input sanitization via `InputValidator`.

**Authentication:** Cookie-based JWT. JWT stored in an HttpOnly cookie (`JWT_COOKIE_NAME`). Browser fingerprint cookie (`fcookie`) set by frontend for fraud detection. Session tracked via `B_COOKIE` and `USER_COOKIE`. Audit entity listeners embed `requestId` and `sessionId` on every write.
