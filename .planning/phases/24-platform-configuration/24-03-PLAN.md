In admin.api.js, add two new functions to the adminApi export object (after the last function,
before the closing brace):

```javascript
/**
 * Get all platform MSISDNs (one per provider).
 * Returns: [{ provider: 'ORANGE', platformMsisdn: '...' }, { provider: 'MTN', platformMsisdn: '...' }]
 */
getPlatformConfig() {
  return api.get('/v1/admin/platform-config')
},

/**
 * Update the platform MSISDN for a specific provider.
 * @param {string} provider - 'ORANGE' or 'MTN'
 * @param {string} platformMsisdn - new MSISDN value
 */
updatePlatformConfig(provider, platformMsisdn) {
  return api.put(`/v1/admin/platform-config/${provider}`, { provider, platformMsisdn })
},
```

Create PlatformConfigPage.vue in src/frontend/src/pages/admin/:
- Use &lt;script setup&gt; Composition API (no defineComponent wrapper — matches all existing pages)
- Imports: { ref, onMounted } from 'vue', { useQuasar } from 'quasar', { adminApi } from 'src/api/admin.api'
- No router needed (no navigation on this page)
- Reactive state:
  - const configs = ref([])         // array of { provider, platformMsisdn }
  - const isLoading = ref(false)
  - const savingProvider = ref(null) // tracks which provider is currently saving (or null)
  - const editValues = ref({})       // { ORANGE: '...', MTN: '...' } — local edits before save

- onMounted: call adminApi.getPlatformConfig(), populate configs.value and editValues.value
  with each config's platformMsisdn keyed by provider name. Handle errors by showing a Quasar
  notification ($q.notify).

- saveProvider(provider) async function:
  - Set savingProvider.value = provider (shows loading state on that provider's button)
  - Call adminApi.updatePlatformConfig(provider, editValues.value[provider])
  - On success: update configs.value entry for that provider with the new msisdn; show success notify
  - On error: show error notify; do NOT reset editValues (user keeps their typed value to retry)
  - Finally: savingProvider.value = null

- Template structure (Quasar components):
  - q-page with q-card for each provider (use v-for="config in configs")
  - Inside each card: q-card-section with title (config.provider), q-input bound to
    editValues[config.provider], q-btn "Save" that calls saveProvider(config.provider)
    with :loading="savingProvider === config.provider"
  - Show a q-banner or q-inner-loading while isLoading is true during initial fetch

- Prettier style: no semicolons, single quotes, 100-char print width
