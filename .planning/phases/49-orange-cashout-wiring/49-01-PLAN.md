<objective>
Add a nullable `feeAmount` field to `PaymentCommand` so that downstream ports (starting with `OrangeMoneyPort.initiateCashout` in Plan 02) can observe the fee computed by `FeeEvaluationService`. Wire `PaymentOrchestrator` to enrich the in-flight command with the evaluated fee via a new `withFeeAmount` helper, and provide a backward-compatible 13-arg constructor so that every existing caller compiles unchanged.

Purpose: CASHOUT-01. The disbursement ledger writer in Plan 02 needs the fee at the port boundary. Without this plan the port has no way to obtain the fee; with it, the orchestrator-computed fee flows cleanly into the command value object.

Output: Updated `PaymentCommand.java` with a 14th record component (`feeAmount`), a 13-arg compat constructor, and an instance method `withFeeAmount(BigDecimal)`. Updated `PaymentOrchestrator.initiate()` that rebinds the local `cmd` to `cmd.withFeeAmount(fee)` immediately after fee evaluation. No test files are touched in this plan; the existing integration suite is the regression signal.
</objective>
