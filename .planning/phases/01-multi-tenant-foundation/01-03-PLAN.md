The current TenantAdminResource constructor takes only TenantService. Add ApiKeyService as a second constructor argument. Spring will inject it automatically (both are @Service beans).

Add two new handler methods to the class. Do NOT alter the existing createTenant() method or its associated records (CreateTenantRequest, TenantCreationResponse).

**New endpoint 1 — rotate:**

```
POST /v1/admin/tenants/{tenantId}/keys/{keyId}/rotate
```

- Path variables: `tenantId` (Long), `keyId` (Long)
- No request body
- Returns: 200 OK with an `ApiKeyDto` carrying the NEW key's id, keyPrefix, environment, and rawKey (shown once)
- Implementation: call `apiKeyService.rotate(keyId)`, which returns `ApiKeyService.ApiKeyAndRawKey`. Map `result.entity()` fields into an `ApiKeyDto`.
- The `tenantId` path variable is present for URL consistency and future ownership validation. For now, use it only as a path segment — do NOT add a DB ownership check in this plan (the service-layer test already covers that the key belongs to a tenant; a separate authorization concern belongs in a later security phase).

**New endpoint 2 — revoke:**

```
DELETE /v1/admin/tenants/{tenantId}/keys/{keyId}
```

- Path variables: `tenantId` (Long), `keyId` (Long)
- No request body
- Returns: 204 No Content, no body
- Implementation: call `apiKeyService.revoke(keyId)` and return void with `@ResponseStatus(HttpStatus.NO_CONTENT)`.

The updated class should look like this (showing only the new additions — keep existing code intact):

```java
import com.softropic.payam.tenant.service.ApiKeyService;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.ResponseStatus;

// Constructor update:
public TenantAdminResource(TenantService tenantService, ApiKeyService apiKeyService) {
    this.tenantService = tenantService;
    this.apiKeyService = apiKeyService;
}

// New method 1:
@PostMapping("/{tenantId}/keys/{keyId}/rotate")
public ApiKeyDto rotateKey(@PathVariable Long tenantId, @PathVariable Long keyId) {
    ApiKeyService.ApiKeyAndRawKey result = apiKeyService.rotate(keyId);
    return new ApiKeyDto(
        result.entity().getId(),
        result.entity().getKeyPrefix(),
        result.entity().getEnvironment(),
        result.rawKey()   // new raw key — shown once, never stored
    );
}

// New method 2:
@DeleteMapping("/{tenantId}/keys/{keyId}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void revokeKey(@PathVariable Long tenantId, @PathVariable Long keyId) {
    apiKeyService.revoke(keyId);
}
```

Do NOT log the rawKey in either method. The rawKey in the rotate response is the same transient value returned by ApiKeyService.generateAndStore() inside rotate() — it is never persisted.

**Test 1 — rotateKey_returns200_withNewRawKey:**

```
POST /v1/admin/tenants/{tenantId}/keys/{keyId}/rotate
```

- HTTP 200
- Response body deserializes to `ApiKeyDto`

- `apiKeyDto.id()` is not equal to the original `keyId` (rotate creates a new DB row)

- Response body is empty

**Test 3 — rotateKey_unknownKeyId_returns404:**

Call `POST /v1/admin/tenants/{tenantId}/keys/999999/rotate` with a valid X-Api-Key header. Assert HTTP 404 (EntityNotFoundException from ApiKeyService maps to 404 via Spring's default exception handling or @ControllerAdvice).

Note on authentication: The test creates a tenant and uses its own rawKey to authenticate the subsequent rotate/revoke calls. This is valid because the filter chain authenticates any valid key on any `/v1/**` path — there is no per-resource ownership check at this layer yet.
