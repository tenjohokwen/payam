public final class TenantContext {
    private static final ThreadLocal<String> CURRENT_TENANT = new ThreadLocal<>();

    public static void set(String tenantId) {
        CURRENT_TENANT.set(tenantId);
    }

    public static String get() {
        return CURRENT_TENANT.get();

    public static void clear() {
        CURRENT_TENANT.remove();   // remove(), NOT set(null) — avoids memory leak in thread pools

    private TenantContext() {}

**Step C — Create ApiKeyAuthenticationFilter**

Package: `com.softropic.payam.tenant.config`
Extends: `OncePerRequestFilter`

CRITICAL rules:
1. Read header `X-Api-Key`. If absent, send 401 and return immediately (do NOT continue filter chain).
2. Call `apiKeyService.authenticate(rawKey)` — this hashes internally and queries with grace window.
3. On success: call `TenantContext.set(tenantRef)` and set a `UsernamePasswordAuthenticationToken` in `SecurityContextHolder`.
4. ALWAYS call `TenantContext.clear()` in the `finally` block — even on exception paths.
5. Do NOT log the raw key value. Do NOT print `rawKey` in any log statement.

IMPORTANT — lazy loading: `ApiKeyService.authenticate()` is `@Transactional(readOnly = true)`. The `TenantApiKey` returned has its `tenant` association loaded via `JOIN FETCH` in `TenantApiKeyRepository.findValidKeyByHash` (see Plan 01-01, Task 2, Step C). This means `tenantApiKey.getTenant().getTenantRef()` and `tenantApiKey.getTenant().getId()` are safe to call here even though the transaction has already closed. Do NOT call `tenantApiKey.getTenant()` if the repository query does not use `JOIN FETCH` — that would cause a `LazyInitializationException` because `spring.jpa.properties.hibernate.enable_lazy_load_no_trans` is `false` in this project.

```java
@Component
public class ApiKeyAuthenticationFilter extends OncePerRequestFilter {

    private static final String API_KEY_HEADER = "X-Api-Key";
    private static final Logger log = LoggerFactory.getLogger(ApiKeyAuthenticationFilter.class);

    private final ApiKeyService apiKeyService;

    public ApiKeyAuthenticationFilter(ApiKeyService apiKeyService) {
        this.apiKeyService = apiKeyService;
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        String rawKey = request.getHeader(API_KEY_HEADER);
        if (rawKey == null || rawKey.isBlank()) {
            response.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Missing X-Api-Key header");
            return;
        }

        TenantApiKey tenantApiKey;
        try {
            tenantApiKey = apiKeyService.authenticate(rawKey);
        } catch (Exception e) {
            log.warn("API key authentication failed for prefix [{}]",
                rawKey.length() >= 8 ? rawKey.substring(0, 8) : "[short]");
            response.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Invalid or expired API key");
            return;
        }

        String tenantRef = tenantApiKey.getTenant().getTenantRef();
        Long   tenantId  = tenantApiKey.getTenant().getId();
        TenantContext.set(tenantRef);

        TenantPrincipal principal = new TenantPrincipal(tenantRef, tenantId);
        UsernamePasswordAuthenticationToken auth =
            new UsernamePasswordAuthenticationToken(principal, null, principal.getAuthorities());
        SecurityContextHolder.getContext().setAuthentication(auth);

        try {
            chain.doFilter(request, response);
        } finally {
            TenantContext.clear();   // ALWAYS clear — servlet containers reuse threads
            SecurityContextHolder.clearContext();
        }
    }
}
```

Note on log line: log the first 8 chars (the key_prefix) for debugging, not the full raw key. This matches the `key_prefix` column purpose.

**Step A — Create TenantSecurityConfig**

Package: `com.softropic.payam.tenant.config`

This is the most security-sensitive file in Phase 1. Follow these rules precisely:

1. `@Order(1)` on the `@Bean` — must be lower number than the existing `SecurityConfiguration.filterChain` (which has no `@Order`, defaulting to `Integer.MAX_VALUE`).
2. `securityMatcher("/v1/**")` — scopes this chain exclusively to tenant API paths. Requests to `/api/**`, `/manage/**`, and `/authenticate` are NOT intercepted by this chain.
3. CSRF disabled — API clients, not browsers.
4. Session management: STATELESS — no HTTP session created.
5. **PUBLIC_ENDPOINTS first**: Before `anyRequest().authenticated()`, explicitly permit all paths listed in `AppEndpoints.PUBLIC_ENDPOINTS` (which includes `/v1/account/register**`, `/v1/account/activate/**`, `/v1/account/reset_password/init`, `/v1/account/reset_password/finish`, etc.). Without this, the `@Order(1)` chain would intercept those paths and return 401 — breaking existing `SecurityFilterChainIT` tests.
6. `addFilterBefore(apiKeyFilter, UsernamePasswordAuthenticationFilter.class)`.
7. Do NOT wire `ClientIdAccessDecisionManager` into this chain — that is for the JWT chain only (see SecurityConfiguration.java).

```java
@Configuration
public class TenantSecurityConfig {

    @Bean
    @Order(1)
    public SecurityFilterChain tenantApiKeyFilterChain(HttpSecurity http,
                                                       ApiKeyAuthenticationFilter apiKeyFilter)
                                                       throws Exception {
        String[] publicPaths = AppEndpoints.PUBLIC_ENDPOINTS.toArray(new String[0]);

        http
            .securityMatcher("/v1/**")
            .csrf(AbstractHttpConfigurer::disable)
            .sessionManagement(sm ->
                sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers(publicPaths).permitAll()   // permit public paths BEFORE authenticated()
                .anyRequest().authenticated())
            .addFilterBefore(apiKeyFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }
}
```

VERIFY the existing `SecurityConfiguration.filterChain` bean has no `@Order` annotation — if it does have one, they must not conflict. Looking at the existing code: it has no `@Order`, so it defaults to lowest priority. No changes needed to `SecurityConfiguration.java`.

WHY the public-path permit matters: `AppEndpoints.PUBLIC_ENDPOINTS` contains `/v1/account/**` paths that are `.permitAll()` in the JWT chain. With `@Order(1)` now claiming all `/v1/**` first, those paths would never reach the JWT chain. The `requestMatchers(publicPaths).permitAll()` line in this chain passes them through unauthenticated, matching the existing behavior. `SecurityFilterChainIT` tests these paths with `X-Client-Id` (not `X-Api-Key`) and must remain green.

**Step B — Create TenantContextTaskDecorator**

```java
public class TenantContextTaskDecorator implements TaskDecorator {

    @Override
    public Runnable decorate(Runnable task) {
        String tenantId = TenantContext.get();   // captured on caller thread
        return () -> {
            try {
                TenantContext.set(tenantId);
                task.run();
            } finally {
                TenantContext.clear();
            }
        };
    }
}
```

**Step D — Create V2__idempotency_key_schema.sql**

File: `src/main/resources/db/migration/V2__idempotency_key_schema.sql`

This table is the schema foundation for Phase 2's idempotency enforcement. Phase 1 only creates the table; Phase 2 adds the runtime lookup logic.

```sql
CREATE TABLE main.idempotency_key (
    id                  BIGINT PRIMARY KEY,
    tenant_id           BIGINT NOT NULL REFERENCES main.tenant(id),
    idempotency_key     VARCHAR(255) NOT NULL,
    response_body       TEXT,
    http_status         INT,
    created_date        TIMESTAMP NOT NULL DEFAULT NOW(),
    expires_at          TIMESTAMP NOT NULL,
    CONSTRAINT uq_idempotency_tenant_key UNIQUE (tenant_id, idempotency_key)
);

CREATE INDEX idx_idempotency_tenant_key ON main.idempotency_key(tenant_id, idempotency_key);
CREATE INDEX idx_idempotency_expires_at ON main.idempotency_key(expires_at);
```

The composite UNIQUE constraint on `(tenant_id, idempotency_key)` makes cross-tenant collision structurally impossible at the database level, satisfying Phase 1 Success Criterion 5.
