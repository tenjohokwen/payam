<objective>
Wave 2: Retire the wallet model at the application layer and extend the `DisbursementStatus` state machine with `PENDING_ADMIN_APPROVAL`. This plan completes Phase 54 by aligning Java with the V31 schema (Plan 02) and unblocks Phase 55, which assumes a fee-free, wallet-free orchestrator and a state machine that supports admin approval.

Purpose: Plan 02 dropped `reserved_amount` from the database. Until this plan removes the matching Hibernate field, ANY integration test that boots the Spring context fails at startup. This plan must be executed and committed in the same wave-graph step as Plan 02 (i.e. as soon as Plan 02's `DisbursementTransactionRefIT` is GREEN). Plan 03 is the application-layer half of SCHEMA-03 ("merchant_wallet_balance retired at the application layer (all reads/writes removed from code)").

Output:
- `Disbursement.java` — `reservedAmount` field removed
- `DisbursementService.create()` — `reservedAmount` parameter dropped from signature; persisted row no longer carries the value
- `DisbursementOrchestrator` — `feeService` and `walletBalanceService` fields/constructor params/calls removed; `confirm()` rebuilt around `BigDecimal.ZERO` fee and `dsb.getAmount()` total
- `DisbursementCallbackTransitionService` — `walletBalanceService` field/constructor param/call removed
- `DisbursementResource.toListItem()` — fee derivation simplified to `BigDecimal.ZERO`
- `DisbursementStatus` — `PENDING_ADMIN_APPROVAL` added; `INITIATED.allowedTransitions()` extended to include it
- `DisbursementStatusTest` — coverage for the new state
- `DisbursementRepositoryIT` and `DisbursementCallbackTransitionServiceTest` — `.reservedAmount(...)` builder calls removed
- Final `mvn verify` is GREEN — Phase 54 is shippable

What this plan does NOT do:
- Does NOT remove `WalletBalanceService` bean class itself (Phase 57 V32 drops the table; only then is the service code deleted)
- Does NOT remove `MerchantWalletBalance` entity or `MerchantWalletBalanceRepository` (same — they become unreachable but stay)
- Does NOT introduce admin-approval flow logic (Phase 56 owns that — this plan only adds the enum value + state transitions so Phase 56 has a target to transition INTO)
- Does NOT touch `DisbursementOrchestratorTest` if it does not reference the removed dependencies (verify with grep first; only edit if breaking)
</objective>

    import com.softropic.payam.transaction.contract.exception.IllegalStateTransitionException;

    import java.util.EnumSet;
    import java.util.Set;

    /**
     * Lifecycle state machine for Disbursement.
     *
     * Terminal states: SUCCESS, FAILED, EXPIRED — no outbound transitions.
     *
     * <p>Two distinct gating states co-exist as of v11 Phase 54:
     * <ul>
     *   <li><b>PENDING_CONFIRMATION</b> — merchant step-up: amount &gt; 500,000 XAF requires the
     *       tenant to call /confirm before provider dispatch (SEC-04, v10).</li>
     *   <li><b>PENDING_ADMIN_APPROVAL</b> — Platform Ops approval: amount &gt; admin-approval
     *       threshold gates dispatch behind an internal approval (Phase 56 ADMIN-01..03).
     *       Auto-expires after admin-approval-timeout-hours; releases claims to RELEASED on expiry.</li>
     * </ul>
     */
    public enum DisbursementStatus {

        INITIATED {
            @Override
            public Set<DisbursementStatus> allowedTransitions() {
                return EnumSet.of(PENDING_CONFIRMATION, PENDING_ADMIN_APPROVAL, PROCESSING, FAILED);
            }
        },
        PENDING_CONFIRMATION {
            @Override
            public Set<DisbursementStatus> allowedTransitions() {
                return EnumSet.of(PROCESSING, EXPIRED, FAILED);
            }
        },
        PENDING_ADMIN_APPROVAL {
            @Override
            public Set<DisbursementStatus> allowedTransitions() {
                // Phase 56 ADMIN-01: admin approves → PROCESSING; ADMIN-03 timeout → EXPIRED.
                // Failure paths (rejection, system errors) route through PROCESSING first.
                return EnumSet.of(PROCESSING, EXPIRED);
            }
        },
        PROCESSING {
            @Override
            public Set<DisbursementStatus> allowedTransitions() {
                return EnumSet.of(SUCCESS, FAILED, EXPIRED);
            }
        },
        SUCCESS {
            @Override
            public Set<DisbursementStatus> allowedTransitions() {
                return EnumSet.noneOf(DisbursementStatus.class);
            }
        },
        FAILED {
            @Override
            public Set<DisbursementStatus> allowedTransitions() {
                return EnumSet.noneOf(DisbursementStatus.class);
            }
        },
        EXPIRED {
            @Override
            public Set<DisbursementStatus> allowedTransitions() {
                return EnumSet.noneOf(DisbursementStatus.class);
            }
        };

        public abstract Set<DisbursementStatus> allowedTransitions();

        public DisbursementStatus transitionTo(DisbursementStatus next) {
            if (!allowedTransitions().contains(next)) {
                throw new IllegalStateTransitionException(
                    "Invalid disbursement state transition: " + this.name() + " -> " + next.name()
                    + ". Allowed transitions from " + this.name() + ": " + allowedTransitions()
                );
            }
            return next;
        }
