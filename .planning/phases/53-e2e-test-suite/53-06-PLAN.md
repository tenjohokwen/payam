DisbursementFraudEvaluationService — `src/main/java/com/softropic/payam/disbursement/service/DisbursementFraudEvaluationService.java`:
- Constants:
  - `BLOCKLIST_KEY = "fraud:dsb:msisdn:blocklist"` (Redis SET key)
  - `BLOCK_THRESHOLD = 80` (strictly greater — score == 80 ALLOWS through)
  - `NEW_RECIPIENT_WEIGHT = 15` (new recipient MSISDN signal)
  - `BLOCKLIST_WEIGHT = 80` (Redis SET membership signal)
- Logic: score > 80 → FraudDecision.block (returns FRAUD_BLOCK error code via the orchestrator)

CRITICAL: A blocklist hit alone gives 80 points (NOT > 80, so NOT blocking). Must combine with another signal to exceed threshold. NEW_RECIPIENT (+15) on top of BLOCKLIST (+80) = 95, which is > 80 and triggers block. Use a fresh tenant + a never-before-seen recipient MSISDN for guaranteed blocklist+new=95 score.

To seed the blocklist:
```java
@Autowired StringRedisTemplate redis;
redis.opsForSet().add("fraud:dsb:msisdn:blocklist", "+237671999000");
```

The MSISDN string format must match exactly what the orchestrator passes to `redis.opsForSet().isMember(BLOCKLIST_KEY, recipientMsisdn)`. Per DisbursementFraudEvaluationService.evaluate signature, this is the recipientMsisdn from the request as-is (E.164, e.g. "+237671999000"). Seed it verbatim.

DisbursementOrchestratorError.FRAUD_BLOCK.getErrorCode() == "FRAUD_BLOCK" → maps to HTTP 422 in DisbursementResource.resolveHttpStatus.

For the idempotency race:
- All 20 threads must use the SAME Idempotency-Key string.
- The first thread to obtain the idempotency lock writes a disbursement row and calls MTN /v1_0/transfer.
- Subsequent threads receive the cached response (errorCode=null OR errorCode=DISBURSEMENT_ALREADY_PROCESSING — both map to 202 in the controller).
- Idempotency namespace: `idempotency:dsb:<tenantId>:<key>` Redis (per SEC-01).

Reference race pattern: ConcurrentIdempotencyRaceTest in src/test/java/com/softropic/payam/e2e/domain/ — adapt for /v1/disbursements with same idempotency key.
