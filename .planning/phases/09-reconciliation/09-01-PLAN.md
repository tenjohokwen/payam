**MtnReportAdapter** (`@Component implements ProviderReportPort`) — uses the existing `MtnMoMoPort` bean. In `fetchProviderRecord()`:
- Call `mtnMoMoPort.getTransactionStatus(providerRef)`.
- Map the result to `ProviderTransactionRecord(providerRef, result.rawStatus(), null, false)`. MTN status API does not return amount; `providerAmount` stays null.
- Catch `HttpClientException` and `RuntimeException` — on any exception log WARN and return `ProviderTransactionRecord(providerRef, null, null, true)` (unconfirmed).
- NOT a `@Qualifier`-named bean — the `ReconciliationService` maps by provider enum key (see below).

**OrangeReportAdapter** (`@Component implements ProviderReportPort`) — uses the existing `OrangeMoneyPort` bean. In `fetchProviderRecord()`:
- Call `orangeMoneyPort.getTransactionStatus(providerRef)` (or equivalent status-check method that exists on OrangeMoneyPort — check its method signatures and use the correct one).
- Any Orange `createtime` string encountered in the response MUST be parsed via `OrangeTimeUtil.parseOrangeTimestamp(createtime)` — never raw string comparison. (If the status response does not return createtime, this guard is not needed but must be noted in a comment.)
- Catch ALL exceptions (including `CallNotPermittedException`) — on any exception log WARN and return `ProviderTransactionRecord(providerRef, null, null, true)` (unconfirmed). This is the resilience requirement: Orange adapter MUST never propagate exceptions to ReconciliationService.
- Return `ProviderTransactionRecord(providerRef, result.rawStatus(), null, false)` on success.

**LedgerSnapshotService** (`@Service`) — read-only ledger query. Single method:
```java
List<Transaction> findTransactionsForDateAndProvider(LocalDate date, MobilePaymentProvider provider)
```
Uses `TransactionRepository` to find transactions where `createdDate` falls within `[date 00:00 UTC, date+1 00:00 UTC)` and `provider == provider`. Only include transactions with a non-null `providerRef` (cannot reconcile without a provider reference). Only include transactions with final or terminal statuses (SUCCESS, FAILED) PLUS PROCESSING — include PROCESSING so mismatches can be detected. Do NOT include INITIATED/AUTH_PENDING/AUTHORIZED (too early in lifecycle to reconcile).

Add the JPQL query to `TransactionRepository`:
```java
@Query("SELECT t FROM Transaction t WHERE t.provider = :provider " +
       "AND t.createdDate >= :from AND t.createdDate < :to " +
       "AND t.txStatus IN ('SUCCESS','FAILED','PROCESSING') " +
       "AND t.providerRef IS NOT NULL")
List<Transaction> findForReconciliation(
    @Param("provider") MobilePaymentProvider provider,
    @Param("from") Instant from,
    @Param("to") Instant to);
```

**ReconciliationService** (`@Service`) — orchestrates reconciliation for one provider+date pair. Constructor-injected: `TransactionRepository`, `LedgerSnapshotService`, `ReconciliationReportRepository`, `ReconciliationDiscrepancyRepository`, and `Map<MobilePaymentProvider, ProviderReportPort> providerReportPorts` (Spring injects all beans implementing ProviderReportPort; use `@Autowired Map<String, ProviderReportPort>` and map by bean name, or use a `List<ProviderReportPort>` with an identifier method — simplest: inject both adapters explicitly with `@Qualifier` on each adapter or use a dedicated `ProviderReportPortRegistry @Component` that returns the correct adapter by provider enum).

Recommended: add a `MobilePaymentProvider provider()` default method to `ProviderReportPort`, implemented by each adapter returning `MTN` and `ORANGE` respectively. Then inject `List<ProviderReportPort>` and build the map in the service constructor.

Main method `runForDate(LocalDate reportDate)`:
1. For each provider in `[MTN, ORANGE]`:
   a. Create a `ReconciliationReport` entity, save with status='IN_PROGRESS'.
   b. Fetch `List<Transaction> ledgerTxs = ledgerSnapshotService.findTransactionsForDateAndProvider(reportDate, provider)`.
   c. For each `tx` in `ledgerTxs`:
      - Call `port.fetchProviderRecord(tx.getProviderRef(), reportDate)`.
      - If `record.unconfirmed()`: build discrepancy with type=UNCONFIRMED, severity=LOW.
      - Else if `record.providerStatus()` is null or indicates "not found": build MISSING_IN_PROVIDER, severity=HIGH.
      - Else compare statuses: if they differ and both are final → STATUS_MISMATCH (MEDIUM). If amounts differ (and both non-null) → AMOUNT_MISMATCH (HIGH). If both match → matched.
   d. Update report counts: `totalChecked = ledgerTxs.size()`, `totalMatched`, `totalDiscrepancies`.
   e. Save all discrepancy entities, update report status to 'COMPLETE'.
2. Log summary per provider at INFO level.

Exception handling: wrap each provider loop in try/catch so one provider failure does not abort the other.

**ReconciliationJob** (`@Component`, extends `QuartzJobBean`) — pattern exactly as `WebhookDeliveryJob`. `@Transactional` on `executeInternal()` (NOT on `execute()` which is final). Constructor-inject `ReconciliationService`. In `executeInternal()`:
```java
LocalDate yesterday = LocalDate.now(ZoneOffset.UTC).minusDays(1);
log.info("ReconciliationJob: running for date {}", yesterday);
reconciliationService.runForDate(yesterday);
```
Catch top-level exceptions and log ERROR to prevent Quartz from unscheduling the trigger.

**ReconciliationSchedulerConfig** (`@Configuration`) — uses CronScheduleBuilder for daily 02:00 UTC:
```java
@Bean
public JobDetail reconciliationJobDetail() {
    return JobBuilder.newJob(ReconciliationJob.class)
        .withIdentity("reconciliationJob")
        .storeDurably()
        .build();
}

@Bean
public Trigger reconciliationTrigger(JobDetail reconciliationJobDetail) {
    return TriggerBuilder.newTrigger()
        .forJob(reconciliationJobDetail)
        .withIdentity("reconciliationTrigger")
        .withSchedule(CronScheduleBuilder.cronSchedule("0 0 2 * * ?"))
        .build();
}
```
