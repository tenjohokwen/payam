## Interaction Contracts

### Add Provider Dialog — PIN Feedback (the interaction change in Phase 45)

| State | Trigger | Behavior |
|-------|---------|----------|
| Dialog open | "Add Provider" button click | Dialog renders; PIN field is type=password, empty, no timer |
| Eye toggle | Click visibility icon | Toggles `dialogPinVisible`; no API call; no countdown (PIN-09) |
| Submit with PIN | Click "Add" with non-blank PIN | `addProvider()` calls PUT; on success notify shows `${provider} configuration added (PIN set)`; card renders with `pinConfigured: true` |
| Submit without PIN | Click "Add" with empty PIN | `addProvider()` calls PUT; on success notify shows `${provider} configuration added`; card renders with `pinConfigured: false` |
| Validation error (400) | Backend rejects PIN pattern | Notify: "PIN must be 4–8 alphanumeric characters." |
| Network error | PUT fails (non-400) | Notify: `Failed to add ${provider} configuration` |
| Cancel | Click "Cancel" | Dialog closes; state reset; no API call; no confirmation required |

### Provider Card PIN Reveal (unchanged from Phase 43 — recorded for executor reference)

| State | Trigger | Behavior |
|-------|---------|----------|
| Masked | Page load | PIN field type=password, empty, pinRevealed=false |
| Reveal | Click eye icon | GET /{provider}/pin; populate field; type=text; start 60s countdown |
| Re-mask (manual) | Click eye icon again | Immediately type=password; value cleared; countdown cancelled |
| Re-mask (auto) | 60s elapsed | type=password; value cleared; countdown interval cleared |
