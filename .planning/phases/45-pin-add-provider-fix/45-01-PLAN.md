<objective>
Close GAP-01 from the v8 milestone audit: the `orElseGet` branch of
`PlatformConfigService.update()` today silently discards any PIN supplied when
creating a brand-new provider row, so PIN entered in the Add Provider dialog is
never persisted on first creation. This plan extends the `orElseGet` branch to
encrypt and persist the PIN (mirroring the `map` branch pattern), adds new unit
and integration test coverage, and enriches the Add Provider success notify so
the admin sees explicit confirmation that the PIN was stored.

Purpose: PIN-09 — the Add Provider dialog already renders the masked PIN input
with eye toggle (visual spec satisfied by Phase 43); this phase closes the
FUNCTIONAL gap so that a PIN typed into that input is actually persisted and
the UI confirms it.

Output: Backend `orElseGet` branch symmetric with `map` branch for PIN
persistence, 2 new unit tests + 2 new IT tests, 1 notify-string enhancement in
the Vue page. `mvn verify` green; admin can add a new provider with PIN and
see "(PIN set)" in the success snackbar.
</objective>
