In admin.api.js, add one new function to the adminApi export object (after updatePlatformConfig,
before the closing brace):

```javascript
/**
 * Get the Spring Boot Actuator health response.
 * Admin JWT required to see component details (components field absent for non-admin).
 * Returns: { status: 'UP'|'DOWN', components?: { [name]: { status, details? } } }
 */
getHealth() {
  return api.get('/manage/health')
},
```

Create HealthDashboardPage.vue in src/frontend/src/pages/admin/:
- Use &lt;script setup&gt; Composition API
- Imports: { ref, onMounted } from 'vue', { useQuasar } from 'quasar', { adminApi } from 'src/api/admin.api'
- Reactive state:
  - const health = ref(null)     // full response: { status, components? }
  - const isLoading = ref(false)

- onMounted: call adminApi.getHealth(), set health.value to the response. Handle errors with
  $q.notify({ type: 'negative', message: 'Failed to load health status' }).

- Computed helper for status color: status === 'UP' ? 'positive' : 'negative'

- Template structure:
  - q-page with padding class
  - div.text-h5.q-mb-md: "System Health"
  - q-inner-loading :showing="isLoading"
  - When health is loaded:
    - Overall status chip: q-chip with :color based on health.status, showing health.status text
    - q-banner v-if="health && !health.components": "Admin access required to view health details."
      Use color="warning" on the q-banner.
    - q-list or div v-if="health && health.components":
      - v-for="(component, name) in health.components" — a q-card per component
      - q-card-section: component name (text-subtitle1), status badge (q-badge), detail entries
      - For details: v-for="(val, key) in (component.details ?? {})" — show "key: val" pairs
      - Status badge: q-badge :color="component.status === 'UP' ? 'positive' : 'negative'"
        :label="component.status"
      - q-space or q-separator between cards

- Prettier style: no semicolons, single quotes, 100-char print width
