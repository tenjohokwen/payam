Create `OutboundWebhookDeliveryE2ETest` as a standalone `@SpringBootTest` class. Do NOT extend `AbstractPayamE2ETest`. The reason is architectural: `AbstractPayamE2ETest` declares `@EnableWireMock` for only the mtn and orange servers. A subclass cannot add to the parent's `@EnableWireMock`. This test needs a third `tenant-wh` WireMock server for the tenant callback endpoint, so all three servers must be declared at this class level, mirroring the `WebhookDeliveryIT` pattern.

**Class-level annotations:**

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@EnableWireMock({
    @ConfigureWireMock(name = "mtn",       baseUrlProperties = {"mtn.collection-base-url"}),
    @ConfigureWireMock(name = "orange",    baseUrlProperties = {"orange.base-url", "orange.pay-url"}),
    @ConfigureWireMock(name = "tenant-wh") // URL assigned dynamically to Tenant entity — no baseUrlProperties
})
@ActiveProfiles("test")
public class OutboundWebhookDeliveryE2ETest {
```

**Test method 1: `@Test void outboundWebhookDeliveredWithHmacSignature()` (FLOWS-HOOK-04)**

This test drives a full inbound-to-outbound cycle: insert PROCESSING transaction, send MTN PUT callback, wait for double-check + outbound delivery, assert HMAC header.

Setup inside the test:
- Stub MTN double-check endpoint:
  ```java
  mtnServer.stubFor(WireMock.get(WireMock.urlPathMatching("/v1_0/requesttopay/.*"))
      .willReturn(WireMock.okJson("{\"status\":\"SUCCESSFUL\",\"financialTransactionId\":\"fin-outbound-001\"}")));
  ```
- Stub the tenant callback endpoint to return 200:
  ```java
  tenantCallbackServer.stubFor(WireMock.post(WireMock.urlEqualTo("/webhook"))
      .willReturn(WireMock.aResponse().withStatus(200).withBody("ok")));
  ```
- Provision tenant with webhook URL and secret:
  ```java
  String webhookUrl = tenantCallbackServer.baseUrl() + "/webhook";
  TenantBuilder.CreatedTenant tenant = new TenantBuilder()
      .withName("Outbound-HMAC-Tenant")
      .withWebhookUrl(webhookUrl, "test-secret")
      .create(tenantService, tenantRepository);
  ```
- Insert PROCESSING MTN transaction via JDBC:
  ```java
  String referenceId = UUID.randomUUID().toString();
  String transactionId = UUID.randomUUID().toString();
  long id = System.nanoTime() & Long.MAX_VALUE;
  transactionTemplate.execute(status -> {
      jdbcTemplate.update(
          "INSERT INTO main.transaction " +
          "(id, created_by, created_date, last_modified_by, last_modified_date, " +
          "transaction_id, trace_id, tenant_id, tx_status, status, provider, amount, currency, provider_ref) " +
          "VALUES (?, 'TEST', NOW(), 'TEST', NOW(), ?, ?, ?, 'PROCESSING', 'ACTIVE', 'MTN', 100, 'XAF', ?)",
          id, transactionId, UUID.randomUUID().toString(), tenant.tenantId(), referenceId);
      return null;
  });
  ```
- Dispatch MTN PUT callback:
  ```java
  MtnCallbackPayload payload = new MtnWebhookPayloadBuilder()
      .forTransaction(transactionId)
      .asSuccessful()
      .build();
  testRestTemplate.exchange(
      "http://localhost:" + serverPort + "/v1/callbacks/mtn",
      HttpMethod.PUT,
      new HttpEntity<>(payload),
      Void.class);
  ```
- Wait for outbound delivery (the @TransactionalEventListener fires after double-check commits):
  ```java
  WebhookDeliveryVerifier verifier = new WebhookDeliveryVerifier(jdbcTemplate, tenantCallbackServer);
  Awaitility.await().atMost(10, TimeUnit.SECONDS).untilAsserted(() ->
      verifier.assertDelivered(transactionId));
  ```
- Assert HMAC header is present and correct:
  ```java
  verifier.assertHmacHeaderPresent(tenantCallbackServer, transactionId);

  // Recompute HMAC from captured request to verify signature correctness
  LoggedRequest logged = tenantCallbackServer
      .findAll(WireMock.postRequestedFor(WireMock.urlEqualTo("/webhook"))).get(0);
  verifier.assertHmacSignatureCorrect(
      logged.getBodyAsString(), "test-secret", logged.getHeader("X-Payam-Signature"));
  ```
  CRITICAL: `WebhookDeliveryVerifier.assertHmacSignatureCorrect()` uses `javax.crypto.Mac.getInstance("HmacSHA256")` internally — do NOT recompute the HMAC yourself using `DigestUtils.sha256Hex()`. Plain SHA-256 ignores the key and will produce a different value than the production HMAC.

**Test method 2: `@Test void outboundWebhookRetriesOn5xx()` (FLOWS-HOOK-05)**

This test verifies that a 5xx response from the tenant callback URL causes the delivery to be marked for retry with exponential backoff.

Setup inside the test:
- Stub MTN double-check endpoint (same as above)
- Stub the tenant callback endpoint to return 503:
  ```java
  tenantCallbackServer.stubFor(WireMock.post(WireMock.urlEqualTo("/webhook"))
      .willReturn(WireMock.aResponse().withStatus(503).withBody("Service Unavailable")));
  ```
- Provision tenant with webhook URL and secret (same `withWebhookUrl` pattern as HMAC test):
  ```java
  String webhookUrl = tenantCallbackServer.baseUrl() + "/webhook";
  TenantBuilder.CreatedTenant tenant = new TenantBuilder()
      .withName("Outbound-Retry-Tenant")
      .withWebhookUrl(webhookUrl, "test-secret")
      .create(tenantService, tenantRepository);
  ```
- Insert PROCESSING MTN transaction via JDBC (same pattern as HMAC test, different `transactionId` / `referenceId`)
- Dispatch MTN PUT callback (same PUT pattern)

Wait for the first inline delivery attempt to complete (the first attempt is synchronous inside `WebhookDeliveryService.enqueue()`):
```java
Thread.sleep(500);
```
`Thread.sleep(500)` is acceptable here because the first attempt is synchronous in `enqueue()`. This is not a busy-wait — it allows the async @TransactionalEventListener to fire and the first attempt to complete before reading the delivery log.

Read the delivery log and assert first attempt state:
```java
List<WebhookDeliveryLog> logs = deliveryLogRepo
    .findByTransactionIdOrderByCreatedDateAsc(transactionId);
assertThat(logs).hasSize(1);
WebhookDeliveryLog log = logs.get(0);
assertThat(log.getDelivered()).isFalse();
assertThat(log.getAttemptCount()).isGreaterThanOrEqualTo(1);
assertThat(log.getHttpStatus()).isEqualTo(503);
assertThat(log.getNextRetryAt()).isNotNull();
```

Verify exponential backoff formula: `2^attemptCount` minutes, capped at 60. After the first failed attempt (`attemptCount=1`), the next retry should be approximately 2 minutes in the future:
```java
assertThat(log.getNextRetryAt()).isAfter(java.time.Instant.now());
```

Trigger two more direct delivery attempts to verify 3 total attempts (bypasses Quartz scheduler timing — deterministic):
```java
webhookDeliveryService.attemptDelivery(logs.get(0));
WebhookDeliveryLog after2 = deliveryLogRepo.findById(logs.get(0).getId()).orElseThrow();
webhookDeliveryService.attemptDelivery(after2);
WebhookDeliveryLog after3 = deliveryLogRepo.findById(logs.get(0).getId()).orElseThrow();
assertThat(after3.getAttemptCount()).isGreaterThanOrEqualTo(3);
assertThat(after3.getDelivered()).isFalse();
assertThat(after3.getNextRetryAt()).isNotNull();
```

Note: `WebhookDeliveryService.MAX_ATTEMPTS = 5`. Calling `attemptDelivery()` twice more after the first attempt brings the count to 3 — still below MAX_ATTEMPTS, so `nextRetryAt` should remain non-null (retry is still scheduled). If MAX_ATTEMPTS is 3, the third attempt would be the final one and `nextRetryAt` may be null — read `WebhookDeliveryService.scheduleRetry()` to confirm and adjust the assertion accordingly.
