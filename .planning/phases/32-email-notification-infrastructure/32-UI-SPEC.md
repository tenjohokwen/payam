# Phase 32 — UI Design Contract

> Visual and interaction contract for transactional HTML email templates.
> The "UI" this phase ships is six Thymeleaf HTML email templates sent to admins and tenants.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable — Spring Boot / Thymeleaf backend |
| Component library | none — inline HTML + inline CSS only |
| Icon library | none — email clients do not reliably render icon fonts |
| Font | system-safe stack: Arial, Helvetica, sans-serif |

**Note:** shadcn gate skipped — this is a Spring Boot Java project, not React/Next.js/Vite.
Email HTML must use inline styles only; linked stylesheets are stripped by most email clients.

---

## Email Rendering Contract

### Template Resolution

`MailService` resolves template names by converting `EmailTemplate` enum values from
`UPPER_UNDERSCORE` to `lowerCamelCase`, prefixed with `mails/` and suffixed with `.html`.

| EmailTemplate enum value | Resolved template path |
|--------------------------|------------------------|
| `TENANT_API_KEY_GENERATED` | `mails/tenantApiKeyGenerated.html` |
| `TENANT_API_KEY_ROTATED` | `mails/tenantApiKeyRotated.html` |
| `TENANT_API_KEY_REVOKED` | `mails/tenantApiKeyRevoked.html` |
| `TENANT_API_KEY_REACTIVATED` | `mails/tenantApiKeyReactivated.html` |
| `TENANT_WEBHOOK_SECRET_REGENERATED` | `mails/tenantWebhookSecretRegenerated.html` |
| `TENANT_STATUS_CHANGED` | `mails/tenantStatusChanged.html` |

### Template Variable Conventions (from existing infrastructure)

All templates receive two root-level variables:
- `recipient` — `Recipient` bean with fields: `firstname`, `lastname`, `email`, `langKey`, `title`, `gender`
- `map` — `Map<String, Object>` containing all event-specific data

Subject lines are resolved from `messages_en.properties` (and `messages_fr.properties`) using
the `subjectKey` declared in the `EmailTemplate` enum.

## Spacing Scale

Email HTML uses inline-style pixel values. The 8-point scale applies within inline `style=""` attributes.

| Token | Value | Email Usage |
|-------|-------|-------------|
| xs | 4px | Icon gaps, tight label padding |
| sm | 8px | Cell padding in detail tables |
| md | 16px | Paragraph margin-bottom, section padding |
| lg | 24px | Main content container padding |
| xl | 32px | Top/bottom body padding |
| 2xl | 48px | Not used in email templates |
| 3xl | 64px | Not used in email templates |

Exceptions: The existing OTP template uses `letter-spacing: 8px` on the code block — this is a
display-specific exception for the OTP code, not a general spacing token. New templates do not
introduce this pattern.

---

## Typography

All values declared as inline `style=""` attributes on HTML elements.

| Role | Size | Weight | Line Height | Element |
|------|------|--------|-------------|---------|
| Body | 16px | 400 (normal) | 1.5 | `<p>` |
| Label | 14px | 400 (normal) | 1.4 | `<small>`, table `<td>` labels |
| Heading | 20px | 600 (bold) | 1.2 | `<h2>` for key detail emphasis |
| Display | 14px | 400 (normal) | 1.4 | `<code>` monospace for key prefix values |

Font family (inline): `font-family: Arial, Helvetica, sans-serif;`
Monospace font (inline, for key prefix only): `font-family: 'Courier New', Courier, monospace;`

**Source:** defaults consistent with existing templates, which use bare `<p>`, `<h2>`, `<strong>`,
and `<small>` without explicit font-size overrides. Phase 32 adds explicit inline sizes for
machine-readable values (key prefixes, environments).

---

## Color

Email clients do not reliably support CSS variables or linked stylesheets.
All colors declared as hex inline styles.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff | Email background, body surface |
| Secondary (30%) | #f5f5f5 | Detail table background (`background-color` on `<table>`) |
| Accent (10%) | #1a56db | Primary informational `<strong>` values, key prefix `<code>` border-left |
| Destructive | #c0392b | Suspension notice paragraph border-left; "If this was not you" alert text |

Accent reserved for: key prefix display blocks, environment label (`PROD` / `DEV`), and the
informational "action taken" line only. Not used on generic body text or closing copy.

Destructive reserved for: suspension event body text only (NOTIF-06 tenant suspended template).
All other templates do not use the destructive color.

**Source:** defaults — no existing email color tokens exist in the codebase. Values chosen to
match the project's admin SPA accent color pattern observed in Phase 26 (blue primary) and to
provide a clear visual distinction for destructive events.

## Template Inventory and Data Contract

### 1. `tenantApiKeyGenerated.html` (NOTIF-01)

**Subject key:** `email.tenant.api_key_generated.title`
**Recipients:** admin notification email + tenant email
**Security constraint:** No raw key material in body. Key prefix only.

| Variable (`map.*`) | Type | Content |
|--------------------|------|---------|
| `tenantName` | String | Tenant display name |
| `keyPrefix` | String | Key prefix (e.g. `prod_abc123`) |
| `environment` | String | `PROD` or `DEV` |
| `generatedAt` | String | ISO-8601 timestamp formatted for display |

**Sections:**
1. Greeting: `Dear {tenantName},`
2. Body: "A new API key has been generated for your account."
3. Detail table: Key prefix, Environment, Generated at
4. Security note: "The full key was shown once at generation time and cannot be retrieved. If you did not request this, contact support."
5. Closing: `#{email.closing}`
6. `<hr/>` + Help Code footer

### 6. `tenantStatusChanged.html` (NOTIF-06)

**Subject key:** `email.tenant.status_changed.title`
**Recipients:** Varies by event type — see security constraints below
**Destructive variant:** Suspension event uses `border-left: 4px solid #c0392b` on the event body paragraph.

| Variable (`map.*`) | Type | Content |
|--------------------|------|---------|
| `tenantName` | String | Tenant display name |
| `eventType` | String | Enum string: `SUSPENDED`, `REACTIVATED`, `EMAIL_CHANGED`, `WEBHOOK_URL_CHANGED` |
| `changedAt` | String | ISO-8601 timestamp formatted for display |
| `oldValue` | String | Present for `EMAIL_CHANGED` and `WEBHOOK_URL_CHANGED` only |
| `newValue` | String | Present for `WEBHOOK_URL_CHANGED` only — absent for `EMAIL_CHANGED` (old address only per REQUIREMENTS.md out-of-scope section) |

**Thymeleaf switch block on `${map.eventType}`:**

| Case | Body copy |
|------|-----------|
| `SUSPENDED` | "Your account has been suspended. All API keys have been revoked. Contact support to resolve this." — styled with destructive border-left |
| `REACTIVATED` | "Your account has been reactivated. A new production API key has been issued — check the admin portal." |
| `EMAIL_CHANGED` | "The email address on this account has been changed. This notification was sent to your previous address. If you did not request this change, contact support immediately." |
| `WEBHOOK_URL_CHANGED` | "Your webhook URL has been updated." + detail table row: Old URL / New URL |
| `*` (default) | "A change has been made to your account." |

**Recipient routing:**
- `SUSPENDED`: admin + tenant (current email address at suspend time)
- `REACTIVATED`: admin + tenant
- `EMAIL_CHANGED`: old address only (requirement NOTIF-06, confirmed by REQUIREMENTS.md out-of-scope)
- `WEBHOOK_URL_CHANGED`: admin + tenant

## Copywriting Contract

| Element | Copy |
|---------|------|
| Greeting (tenant) | `Dear {tenantName},` |
| Greeting (admin) | `Hello,` (no firstname; matches `platformConfigChanged.html` pattern) |
| Closing | `Thanks, the Payam team` (from `#{email.closing}`, source: `messages_en.properties`) |
| Security note — no action taken | `If you did not request this, please contact support immediately.` |
| Security note — key revoked | `If this revocation was unexpected, contact support.` |
| Security note — account suspended | `Your account has been suspended. All API keys have been revoked. Contact support to resolve this.` |
| Security note — email changed | `This notification was sent to your previous address. If you did not request this change, contact support immediately.` |
| Security note — webhook secret | `The new secret can be retrieved from the admin portal. If you did not request this, contact support immediately.` |
| Help code footer | `Help Code: {helpCode}` (from `#{email.common.helpCode}`, source: existing i18n key) |
| Empty state | Not applicable — transactional emails are not shown when there is no data; they are not triggered |
| Error state | Not applicable — delivery failures are handled by `MailManager` circuit breaker + `EmailRetryScheduler`; no user-visible error UI |
| Primary CTA label | None — these emails are informational only; no action links or CTA buttons |
| Destructive confirmation | Not applicable — emails are notifications, not interactive; the action (suspension) has already been confirmed via the admin portal before the email fires |

## HTML Structure Contract

All six templates must follow this structure (matching existing templates):

```html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title th:text="#{email.tenant.{event}.title}">{Fallback title}</title>
</head>
<body style="font-family: Arial, Helvetica, sans-serif; font-size: 16px; line-height: 1.5; color: #333333; background-color: #ffffff; padding: 32px;">

    <p>{greeting}</p>

    <p>{event description}</p>

    <table style="background-color: #f5f5f5; padding: 16px; border-collapse: collapse; width: 100%;">
        <!-- detail rows: label <td> + value <td> -->
    </table>

    <p>{security note}</p>

    <p th:text="#{email.closing}">Thanks, the Payam team</p>

    <hr/>
    <p><small>
        <span th:text="#{email.common.helpCode}">Help Code:</span>
        <span th:text="${map.helpCode}">CODE</span>
    </small></p>

</body>
</html>
```

Key prefix and environment values must use monospace inline styling:
```html
<code style="font-family: 'Courier New', Courier, monospace; font-size: 14px; border-left: 4px solid #1a56db; padding-left: 8px;"
      th:text="${map.keyPrefix}">prod_abc123</code>
```
