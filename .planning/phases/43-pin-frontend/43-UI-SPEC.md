## Visual Hierarchy

Primary visual anchor on each provider card is the `q-input` PIN field. Eye icon is the secondary action (append slot of the PIN field). Save button (`"Save {PROVIDER} Config"`) is the primary CTA and the lowest element in the card reading order — full-width or right-aligned, `color="primary"`.

Reading order within each provider card:
1. Card heading (provider name — `text-h6`)
2. MSISDN input field
3. PIN input field (primary visual anchor — `q-input` with eye-icon append)
4. Countdown caption (visible only when PIN is revealed — `text-caption text-grey`)
5. Save button (primary CTA — `color="primary"`)

## Component Inventory

All new components extend existing Quasar patterns already present in the codebase.

### PIN Input Field (provider card + dialog)

```
q-input
  type="password"  (masked by default)
  v-model="pinValues[config.provider]"
  label="Provider PIN"
  outlined
  dense
  placeholder="Leave blank to keep existing PIN"
  class="q-mb-sm"
  :append slot:
    q-btn
      flat round dense
      :icon="pinRevealed[provider] ? 'visibility_off' : 'visibility'"
      :aria-label="pinRevealed[provider] ? 'Hide PIN' : 'Reveal PIN'"
      @click="togglePin(provider)"
```

`type` attribute is controlled by a separate reactive boolean per provider (`pinInputType[provider]`), toggling between `"password"` and `"text"` — NOT by the `unmasked` boolean controlling visibility, which tracks API state. The Quasar `q-input` password toggle is implemented via the `append` slot with an explicit `q-btn` (same pattern as TenantDetailPage.vue webhook secret, NOT the built-in `:type="isPwd ? 'password' : 'text'"` shortcut, so that the eye icon and countdown can be independently controlled).

### Countdown badge (provider card only — not in dialog)

```html
<div v-if="pinRevealed[provider]" class="text-caption text-grey q-mt-xs">
  Auto-hides in {{ pinCountdown[provider] }}s
</div>
```

## State Design

Per-provider reactive state (keyed by provider string, e.g. `"ORANGE"`, `"MTN"`):

| State variable | Type | Initial value | Description |
|----------------|------|---------------|-------------|
| `pinValues` | `ref({})` | `{}` | v-model for each PIN input; empty string on page load (PIN not pre-fetched) |
| `pinRevealed` | `ref({})` | `{}` (all false) | Whether plaintext is currently shown for a provider |
| `pinTimers` | `{}` (plain object) | `{}` | maskTimer handles per provider (setTimeout refs) |
| `pinCountdownIntervals` | `{}` (plain object) | `{}` | setInterval handles per provider |
| `pinCountdown` | `ref({})` | `{}` | Displayed seconds remaining per provider |

Dialog state (single dialog, no per-provider timer):

| State variable | Type | Initial value | Description |
|----------------|------|---------------|-------------|
| `newProvider.pin` | `string` | `''` | PIN field in Add Provider dialog |

> `onUnmounted`: `clearAllPinTimers()` must be called to prevent interval leaks — mirrors the `clearTimers()` pattern in TenantDetailPage.vue line 435.

## Interaction Contracts

### IC-01: PIN field on page load
- Each provider card renders a `q-input` in password mode (eye-icon append slot) with `model-value = ""` (empty string)
- `pinConfigured: true/false` from GET /platform-config list response is used to set the placeholder dynamically:
  - `pinConfigured === true` → placeholder: `"Leave blank to keep existing PIN"`
  - `pinConfigured === false` → placeholder: `"Optional — 4-8 alphanumeric characters"`
- PIN value is NOT fetched on page load (requirement: PIN-06, field is empty on page load)

### IC-02: Eye icon clicked — reveal
Precondition: `pinRevealed[provider] === false`

1. Call `GET /v1/admin/platform-config/{provider}/pin`
2. On success: set `pinValues[provider] = response.pin`, set `pinRevealed[provider] = true`, set input type to `"text"`, start 60-second countdown timer
3. On 404 (no PIN configured): show `$q.notify({ type: 'warning', message: 'No PIN configured for {provider}' })` — do not change field state
4. On other error: show `$q.notify({ type: 'negative', message: 'Failed to retrieve PIN. Please try again.' })`

Countdown mechanics:
- `pinCountdown[provider] = 60`
- `setInterval(() => { pinCountdown[provider]-- }, 1000)` stored in `pinCountdownIntervals[provider]`
- `setTimeout(() => { reMaskPin(provider) }, 60000)` stored in `pinTimers[provider]`

### IC-03: Eye icon clicked — re-mask (before expiry)
Precondition: `pinRevealed[provider] === true`

1. Call `clearPinTimers(provider)` (clears both setTimeout and setInterval)
2. Set `pinValues[provider] = ''`
3. Set `pinRevealed[provider] = false`
4. Set input type back to `"password"`
5. Set `pinCountdown[provider] = 0`

> No API call on re-mask. Mirrors exact reMask() pattern from TenantDetailPage.vue lines 394–399.

### IC-04: Auto-mask on countdown expiry
Same as IC-03, triggered by the `setTimeout` callback.

### IC-05: Save button
1. Call `PUT /v1/admin/platform-config/{provider}` with body `{ provider, platformMsisdn: editValues[provider], pin: pinValues[provider] || undefined }`
2. Sending `pin: ""` (empty string) or omitting pin → backend preserves existing PIN (PIN-08 semantics)
3. Sending `pin: undefined` in the body: use `pinValues[provider] || undefined` so empty string becomes `undefined` and is omitted from the JSON body
4. On success: show `$q.notify({ type: 'positive', message: '{provider} configuration saved' })`; reMask the PIN field if currently revealed (`reMaskPin(provider)`)
5. On 400 (validation error): show `$q.notify({ type: 'negative', message: 'PIN must be 4–8 alphanumeric characters.' })`
6. On other error: show `$q.notify({ type: 'negative', message: 'Failed to save {provider} configuration. Please try again.' })`

### IC-06: Add Provider dialog — PIN field
- Same `q-input` password pattern with eye icon append slot
- Eye icon toggles `type` between `"password"` and `"text"` only — no API call, no countdown timer (PIN-09: no auto-mask in dialog, admin just typed the value)
- PIN field is optional; submit includes `pin: newProvider.pin || undefined`
- Dialog closes on success; `newProvider.pin` reset to `""` on close

## API Client Additions

Two new methods must be added to `src/frontend/src/api/admin.api.js`:

```js
/**
 * Retrieve decrypted plaintext PIN for a provider.
 * Returns: { pin: string }
 * Throws 404 if no PIN configured.
 */
getPlatformConfigPin(provider) {
  return api.get(`/v1/admin/platform-config/${provider}/pin`)
},

/**
 * Update platform MSISDN and optionally PIN for a provider.
 * @param {string} provider - 'ORANGE' or 'MTN'
 * @param {string} platformMsisdn
 * @param {string|undefined} pin - omit or pass undefined to preserve existing PIN
 */
updatePlatformConfigFull(provider, platformMsisdn, pin) {
  const body = { provider, platformMsisdn }
  if (pin !== undefined && pin !== '') body.pin = pin
  return api.put(`/v1/admin/platform-config/${provider}`, body)
},
```

> The existing `updatePlatformConfig(provider, platformMsisdn)` method in admin.api.js (line 59) must NOT be changed — it is used by other callers. `saveProvider()` in PlatformConfigPage.vue switches to `updatePlatformConfigFull`.
