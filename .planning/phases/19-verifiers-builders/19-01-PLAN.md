    **DatabaseVerifier (VERIF-01)** — constructor: `JdbcTemplate jdbc`
    - `assertPaymentRow(String transactionId, String expectedStatus)` — queries `main.transaction WHERE transaction_id = ?`, asserts `tx_status` equals expectedStatus using AssertJ
    - `assertEventCount(String transactionId, int expectedCount)` — queries `SELECT count(*) FROM main.payment_event_log WHERE transaction_id = ?`, asserts count
    - `assertNoOrphanEvents(String transactionId)` — asserts every row in `payment_event_log` for the transactionId has a corresponding row in `main.transaction`
    - `assertNoDuplicateIdempotencyKey(Long tenantId, String idempotencyKey)` — queries `SELECT count(*) FROM main.idempotency_key WHERE tenant_id = ? AND idempotency_key = ?`, asserts count <= 1. Note: idempotency uniqueness lives in `main.idempotency_key`, NOT `main.transaction`.

    **HashChainVerifier (VERIF-02)** — constructor: `JdbcTemplate jdbc`
    - `assertChainValid(String transactionId)` — loads all rows from `main.payment_event_log WHERE transaction_id = ? ORDER BY id ASC`, then for each row verifies:
      - `event_hash = DigestUtils.sha256Hex(transactionId + "|" + eventType + "|" + statusFrom + "|" + statusTo + "|" + actor + "|" + previousHash)` where statusFrom null is rendered as the literal string `"null"`
      - For the genesis row: `previous_hash = "GENESIS"`
      - For subsequent rows: `previous_hash` equals the `event_hash` of the prior row
      - No out-of-order gap (ids are strictly sequential with no missing rows in the chain)
    - Import: `org.apache.commons.codec.digest.DigestUtils` (already transitive via commons-codec)
    - Do NOT include `traceId`, `metadata`, `createdDate`, or `id` in the canonical string — only the 6 fields above.

    **EventVerifier (VERIF-04)** — constructor: `JdbcTemplate jdbc`
    - `assertEventCount(String transactionId, int expectedCount)` — queries `main.payment_event_log`, asserts count. Note: there is NO Spring Modulith outbox table. The "outbox event publication count" from VERIF-04 refers to rows in `main.payment_event_log`, not any `spring_modulith_events` table.
    - `assertEventSequence(String transactionId, List<String> expectedEventTypes)` — loads event_type values in id ASC order, asserts they equal expectedEventTypes exactly (order matters)
    - `assertEventPresent(String transactionId, String eventType)` — asserts at least one row with matching event_type

    **LedgerVerifier (VERIF-05)** — constructor: `JdbcTemplate jdbc`
    - `assertLedgerBalanced(String transactionId)` — queries `SELECT direction, account_code, amount FROM main.ledger_entry WHERE transaction_id = ?`, asserts: exactly 2 rows exist, one with `direction=DEBIT, account_code=CUSTOMER_WALLET`, one with `direction=CREDIT, account_code=PROVIDER_CLEARING`, and both amounts are equal. These account codes are hardcoded in production `LedgerService` — do not parameterize.
    - `assertEntryCount(String transactionId, int expectedCount)` — asserts row count
    - `assertNoLedgerEntries(String transactionId)` — asserts 0 rows (used for FAILED/fraud-blocked flows)

    **InvariantVerifier (VERIF-03)** — constructor receives all delegates:

    Constructs internally: `DatabaseVerifier`, `HashChainVerifier`, `EventVerifier`, `LedgerVerifier`. Also receives `ProviderCallVerifier`, `WebhookDeliveryVerifier`, `TenantIsolationVerifier` — pass these as constructor parameters or construct them internally from the jdbc/redis/server args (internal construction is simpler).

    Exposes:
    - `assertLedgerBalanced(String transactionId)` — delegates to LedgerVerifier
    - `assertNoDoubleCharge(Long tenantId, String idempotencyKey)` — delegates to DatabaseVerifier.assertNoDuplicateIdempotencyKey
    - `assertTenantIsolation(String transactionId, Long correctTenantId, Long wrongTenantId)` — delegates to TenantIsolationVerifier (construct internally)
    - `assertLegalStateTransition(String transactionId, String expectedStatus)` — delegates to DatabaseVerifier.assertPaymentRow
    - `assertWebhookDoubleCheckFired(String transactionId)` — asserts `SELECT count(*) FROM main.payment_event_log WHERE transaction_id = ? AND event_type IN ('PROVIDER_SUCCESS','PROVIDER_FAILED')` >= 1, indicating the double-check result was appended
    - `assertFraudEvaluatedBeforeProviderCall(String transactionId)` — loads `created_date` for the FRAUD_CHECK_PASSED or FRAUD_CHECK_BLOCKED event row, and asserts it is before or equal to the `created_date` of any PROVIDER_AUTH_REQUESTED event row
    - `assertAll(String transactionId, Long tenantId, String expectedStatus)` — calls assertLedgerBalanced + assertNoDoubleCharge + assertLegalStateTransition + assertChainValid (via HashChainVerifier) for SUCCESS flows

    - `assertRetryScheduled(String transactionId)` — queries `main.webhook_delivery_log WHERE transaction_id = ? AND next_retry_at IS NOT NULL AND delivered = false`, asserts count >= 1
