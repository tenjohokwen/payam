    - `"merchant_key"` — Orange PayRequest credential field; snake_case not caught by existing keys
    - `"merchantKey"` — camelCase variant; caught by "merchant_key"? No — substring of "merchantkey" does not contain "merchant_key". Add explicitly.

    The SENSITIVE_KEYS set in the source uses `Set.of(...)`. Replace the current set definition with the expanded set that includes the three new entries. Keep all existing entries exactly as they are — only add the new ones.

    ```java

        kv("operation", "body_sanitization"),
        kv("status", "PARSE_ERROR"));
    ```
    Do NOT include the exception message (may contain PII from the body). Add kv static import if not present.

    **RestRequestInterceptor.java:**

    This file has four areas to address. Read the full file before making any change.

    **Area 1 — Lines 66-72 (ERROR: response headers + body for 4xx/5xx):**
    Convert the {} placeholder log to kv(). Do NOT log the full headers object. Only log the response status and body (already sanitized):
    ```java
    log.error("Provider API error response",
        kv("operation", "provider_http_call"),
        kv("httpStatus", response.getStatusCode().value()),
        kv("status", "ERROR"));
    ```
    If the body is already being sanitized and logged separately, consolidate. The key constraint: do NOT include response.getHeaders() or any headers object as a log argument.

    **Area 2 — Lines 82-88 (INFO: full response body for 2xx responses):**
    Downgrade from INFO to DEBUG (per research open question 2 recommendation — LOG-BUS-06 structured latency events replace the observability need):
    ```java
    if (log.isDebugEnabled()) {
        log.debug("Provider response body", kv("body", sanitizedBody));
    }
    ```
    Or simply change `log.info(...)` to `log.debug(...)` on the existing call if the body is already sanitized. The body variable must still be routed through BodySanitizer before logging. Verify BodySanitizer.sanitize() is called before this log statement.

    **Area 3 — Line 112 (`"RESPONSE method: {} url: {} status: {} latency: {}"`):**
    Convert to kv():
    ```java
    log.info("Provider HTTP response",
        kv("operation", "provider_http_call"),
        kv("method", method),
        kv("url", url),
        kv("httpStatus", status),
        kv("latencyMs", latency));
    ```

    **Area 4 — Line 128 (`"Error occurred while trying to set txnId for http request with headers: {}"` with httpHeaders):**
    This is the Authorization header exposure risk. Remove headers from the log entirely:
    ```java
    log.warn("Error occurred while trying to set txnId for http request",
        kv("operation", "provider_http_call"),
        kv("status", "TXN_ID_SET_ERROR"));
    ```
    Do NOT include httpHeaders or any headers object as an argument. The exception (if present as a last arg) may be preserved.

    Add static import `import static net.logstash.logback.argument.StructuredArguments.kv;` if not already present.
