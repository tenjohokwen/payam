    **Test 7: circuit_breaker_trips_after_repeated_failures_returns_503** (SC-3)
    This test verifies that Resilience4j trips the MTN circuit breaker after sufficient failures,
    and that PaymentResource correctly returns 503 when CallNotPermittedException is thrown.

    Resilience4j config: `slidingWindowSize=10`, `failureRateThreshold=50` (5 of 10 must fail).
    Strategy: send 10 requests that all fail at the provider (WireMock returns 500), then verify
    the 11th (or a subsequent) call gets 503 from our API (circuit open, no provider call at all).

    Steps:
    1. Stub MTN validateAccountHolder to return 500 (server error — counts as failure for circuit):
       ```java
       mtnServer.stubFor(get(urlPathMatching("/collection/v1_0/accountholder/MSISDN/.*/active"))
           .willReturn(aResponse().withStatus(500)));
       ```
       Note: MtnAccountInactiveException (404) is in ignoreExceptions and does NOT count as a
       failure for the circuit. Use 500 so HttpClientException is thrown, which DOES count.

    2. Send 10 requests, each with a unique idempotencyKey (circuit breaker needs 10 calls in
       the sliding window with ≥50% failures to open):
       ```java
       for (int i = 0; i < 10; i++) {
           String body = buildMtnRequest("+237672000001", "idem-cb-" + i);
           testRestTemplate.exchange("/v1/payments", HttpMethod.POST,
               new HttpEntity<>(body, headersWithKey()), PaymentResponse.class);
           // responses will be 422 (PROVIDER_ERROR) — circuit not yet open
       }
       ```

    3. After 10 failures, the circuit should be OPEN. Verify Resilience4j state directly:
       ```java
       CircuitBreaker cb = circuitBreakerRegistry.circuitBreaker("mtn");
       assertThat(cb.getState()).isEqualTo(CircuitBreaker.State.OPEN);
       ```

    4. Reset WireMock requests (optional — just for clarity): `mtnServer.resetRequests()`

    5. Send the 11th request (circuit is open — WireMock should NOT be called):
       ```java
       ResponseEntity<PaymentResponse> resp = testRestTemplate.exchange(
           "/v1/payments", HttpMethod.POST,
           new HttpEntity<>(buildMtnRequest("+237672000001", "idem-cb-open"), headersWithKey()),
           PaymentResponse.class);
       ```

    6. Assert:
       - Response HTTP status is 503 SERVICE_UNAVAILABLE
       - `resp.getBody().errorCode()` equals "PROVIDER_UNAVAILABLE"
       - WireMock received NO validateAccountHolder call for this last request:
         `mtnServer.verify(0, getRequestedFor(urlPathMatching(".*accountholder.*")))` — or use
         `mtnServer.findAll(...)` after the reset to confirm 0 requests

    IMPORTANT notes for this test:
    - Each of the 10 failing requests needs a UNIQUE idempotencyKey to bypass the idempotency cache
      (otherwise the same key would return the cached response, not calling the provider again)
    - Each failing request also creates a transaction row — tearDown() DELETE handles cleanup
    - If the circuit does not open after 10 requests, check whether `retryExceptions` in the
      Retry config retries on HttpClientException (it should NOT — HttpClientException is not in

    - The MTN token stub must be active for this test (set up in @BeforeEach) — token fetch happens
      before validateAccountHolder; if token fetch fails, the error won't count correctly
