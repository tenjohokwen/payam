<objective>
Fourth wave of Phase 65: redistribute the security-domain types and dispose of the dead-code enums sub-package. After this plan, `common/` will be completely empty.

Three moves, two destinations:

1. **`common.Gender` + `common.consumer` (3 files) → `platform.security.contract`**: All 13 callers of `Gender` live in `platform.security.*` (8 production + 5 test); all 4 callers of `Consumer` live in `platform.security.*`. These types are exclusively used by the security/user domain — moving them to `platform.security.contract` co-locates them with `Principal.java`, `UserDto.java`, `PermutedSecretKey.java`, and the existing contract types already in that package.

2. **`common.enums.{Picker, Unit}` (2 files) → `infrastructure.util`**: Per RESEARCH.md Open Question 2, both have zero external callers anywhere in the codebase. `Picker` is a generic enum utility interface; `Unit` is a measurement enum (legacy remnant — likely dead code). Placing them in `infrastructure.util` is the safest disposition: no callers to break, no domain claim, and a future tech-debt cleanup phase can delete `Unit` if confirmed unused. They still must move to empty `common.enums/` per CMN-04.

This wave depends on Plan 03 because:
- After Plan 03, `common/` contains only `consumer/`, `enums/`, `Gender.java`, and possibly empty `dto/` directory (dto's only file PhoneNumberDto was moved by Plan 02).
- Plan 04 closes out the redistribution; Plan 05 is the final verification gate.

CRITICAL pitfall handling (verified against RESEARCH.md):

- **Pitfall 2 — `platform.security.common.*` MUST NOT be touched**: The packages `com.softropic.payam.platform.security.common.event.*` and `com.softropic.payam.platform.security.common.util.*` already correctly exist and have nothing to do with `com.softropic.payam.common.*`. All sed `find` patterns must be strictly scoped — never use a broad `*/common/*` filter.

When Consumer moves to `platform.security.contract`, this becomes an intra-domain import (`platform.security.contract` → `platform.security.repo`) which is legal and must remain. Do NOT remove or alter it.

- **`Consumer.java` import of `common.Gender`**: At the start of Plan 04, `common.Gender` still exists (Plan 03 didn't touch it). Either is acceptable; sed retargets it automatically.

- **`Consumer.java` import of `common.validation.PhoneNumber`**: Plan 02 already moved `PhoneNumber` to `infrastructure.validation`. At the start of Plan 04, this import has ALREADY been retargeted to `import com.softropic.payam.infrastructure.validation.PhoneNumber;` by Plan 02's sed sweep on common.* callers. Plan 04 must preserve this intact.
