## Spacing Scale

Declared values (must be multiples of 4). Quasar uses utility classes `q-pa-*` / `q-ma-*` / `q-mb-*` / `q-col-gutter-*` mapping to the scale below.

| Token | Value | Quasar class suffix | Usage |
|-------|-------|---------------------|-------|
| xs | 4px | `xs` | Icon gaps, chip padding |
| sm | 8px | `sm` | Compact element spacing, dense input gaps |
| md | 16px | `md` | Default element spacing, card padding |
| lg | 24px | `lg` | Section padding (page header margin-bottom) |
| xl | 32px | `xl` | Layout gaps between major sections |
| 2xl | 48px | — | Major section breaks (not a Quasar class; use inline style if needed) |
| 3xl | 64px | — | Page-level spacing (not used in this phase) |

Exceptions:
- Touch targets on action buttons in q-table rows: minimum 36px height (Quasar `dense` button default). No explicit 44px exception needed — icon-only buttons use `q-btn round dense`.
- Page heading row uses `q-mb-md` (16px) consistently with existing admin pages.

Source: Observed in `PlatformConfigPage.vue` and `TransactionSearchPage.vue`.

## Typography

Quasar applies Roboto via global CSS; no custom font stack needed. Typography roles map directly to Quasar text utility classes.

| Role | Size | Weight | Line Height | Quasar class |
|------|------|--------|-------------|--------------|
| Body | 14px | 400 (regular) | 1.5 | `text-body2` |
| Label / caption | 12px | 400 (regular) | 1.4 | `text-caption` |
| Section heading | 20px | 500 (medium) | 1.2 | `text-h6` |
| Page heading | 24px | 400 (regular) | 1.2 | `text-h5` |

Rules:
- Page heading (`text-h5`) appears once per page at top-left — identical to `TransactionSearchPage` and `PlatformConfigPage` patterns.
- Section headings (`text-h6`) used inside `q-card-section` to label sub-sections (e.g., "API Keys", "Webhook Secret").
- All `q-input` labels use Quasar default label sizing (12px floating, 14px inline).
- Monospace display for raw key and webhook secret: use CSS `font-family: monospace` on the `q-input` element via `:input-style="{ fontFamily: 'monospace' }"`.

Source: Existing admin pages; CONTEXT.md D-10, D-13.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` / `bg-white` | Page background, q-page surface |
| Secondary (30%) | `#f5f5f5` / `bg-grey-2` | q-card backgrounds, q-drawer background |
| Accent (10%) | `#1976d2` ($primary) | Primary action buttons only |
| Destructive | `#c10015` ($negative) | Suspend button, revoke action button |

Accent (`$primary` / `color="primary"`) reserved for:
- "Search" / "Save" / "Generate" / "Rotate" / "Reactivate" action buttons (non-destructive mutations)
- Active nav item highlight in `q-drawer`
- `q-btn color="primary"` for the main page CTA

Destructive (`$negative` / `color="negative"`) reserved for:
- "Revoke" key action button
- "Suspend" tenant status button

Secondary semantic colors:
- `$positive` (`#21ba45`) — `$q.notify({ type: 'positive' })` success toasts; ACTIVE status chip (`color="positive"`)
- `$warning` (`#f2c037`) — ROTATED key status chip (`color="warning"`)
- `$negative` — REVOKED/SUSPENDED status chip (`color="negative"`); error toasts
- Grey (`color="grey"`) — any status not matching ACTIVE/SUSPENDED/ROTATED/REVOKED

Source: `quasar.variables.scss`; CONTEXT.md "Claude's Discretion" (status chip colors).

## Interaction Contracts

### TenantListPage (UI-01)

- Layout: `q-page padding` wrapper, `text-h5 q-mb-md` page heading "Tenants"
- Filter card: `q-card q-mb-md` with `q-select` for status filter (options: ALL, ACTIVE, SUSPENDED) and a "Search" `q-btn color="primary"`
- Table: `q-table` with server-side pagination (`:pagination` + `@request` handler); columns: Tenant Name, Ref, Email, Status (chip), Created; `row-key="tenantRef"`; `@row-click` navigates to `/admin/tenants/:tenantRef`
- Loading state: `:loading="loading"` on `q-table`
- Empty state: q-table built-in no-data slot (see Copywriting Contract)

### TenantDetailPage (UI-02)

- Layout: `q-page padding`; page heading `text-h5` showing tenant name; status toggle button at top-right of heading row
- Load state: `q-inner-loading :showing="isLoading"` overlay
- Inline edit section: three `q-input outlined dense` fields (Name, Email, Webhook URL), each with its own `:loading="saving[field]"` Save `q-btn color="primary"` — identical to `PlatformConfigPage` card pattern
- Status toggle: single `q-btn` in the header — `color="negative" label="Suspend"` when ACTIVE; `color="primary" label="Reactivate"` when SUSPENDED; triggers `$q.dialog()` confirm before API call
- API Keys section: `q-card` with `text-h6` "API Keys", containing a `q-table` (columns: Env, Key Prefix, Status chip, Created Date, Actions); rows sorted PROD first; action buttons are context-sensitive per D-04
- Webhook Secret section: `q-card` with `text-h6` "Webhook Secret"; `q-input type="password" outlined readonly` with eye-icon `q-btn` in `append` slot; countdown timer displayed as caption text when revealed

### OneTimeKeyModal (UI-03)

- `q-dialog persistent` (`:persistent="true"` — no outside-click or Escape dismiss)
- Content: explanatory paragraph, `q-input readonly outlined` with `:input-style="{ fontFamily: 'monospace' }"` displaying raw key, "Copy" `q-btn flat` using Quasar Clipboard API or `navigator.clipboard`
- Gate: `q-checkbox v-model="copied"` with label "I have copied the key and stored it safely"
- Dismiss: `q-btn color="primary" label="Done" :disable="!copied"` — on click, emit `close` event, parent sets `rawKey = null`
- Props: `rawKey: String` (required), `modelValue: Boolean` (visibility control)

### Webhook Secret Reveal (UI-04)

- Eye-icon `q-btn flat round dense icon="visibility"` / `icon="visibility_off"` in input append slot
- On first click: `GET /webhook-secret` → set `secret` ref → `unmasked = true` → start 30s `setTimeout` → on timeout: `secret = null`, `unmasked = false`
- On second click while unmasked: cancel timer, `secret = null`, `unmasked = false` immediately
- Countdown: display remaining seconds as `text-caption text-grey` below the input while unmasked

Source: CONTEXT.md D-13, D-14, D-15.
