<objective>
Replace the broken logback configuration with a correct, production-ready JSON logging pipeline.

Purpose: The current `logback-spring.xml` uses PatternLayoutEncoder (produces text, not JSON), ships a file appender writing to `/var/log/payam/spring.log`, and ships a Loki4j network appender — all of which violate LOG-INF-01, LOG-INF-02, and LOG-INF-03. Furthermore, the file is never loaded because `logging.config` is commented out in both YAML files, so the app starts with default Spring Boot text format. This plan fixes all three problems with configuration changes only — no Java code.

Output: Single ConsoleAppender writing JSON to stdout. `traceId` and `spanId` appear as top-level fields via `<mdc/>` provider. Service identity (`service`, `environment`, `version`) injected via `<pattern>` provider. Config activated in both application profiles.
</objective>

  <name>Task 1: Replace logback-spring.xml with LoggingEventCompositeJsonEncoder stdout config</name>
  <files>src/main/resources/config/logback-spring.xml</files>
  <action>
Replace the entire contents of `src/main/resources/config/logback-spring.xml` with the following. Do not keep any of the existing content.

The new file uses `source="app.environment"` and `source="app.version"` (Spring properties, not raw env vars) so that resolution works reliably whether values come from environment variables (via application.yaml interpolation in Task 2) or are absent (falls back to `defaultValue`).

```xml
<configuration>

    <springProperty name="appName"     source="spring.application.name" defaultValue="payam"/>
    <springProperty name="environment" source="app.environment"         defaultValue="dev"/>
    <springProperty name="appVersion"  source="app.version"             defaultValue="unknown"/>

    <appender name="JSON" class="ch.qos.logback.core.ConsoleAppender">
        <encoder class="net.logstash.logback.encoder.LoggingEventCompositeJsonEncoder">
            <providers>
                <timestamp/>
                <logLevel/>
                <threadName/>
                <loggerName/>
                <message/>
                <mdc/>
                <arguments/>
                <stackTrace/>
                <pattern>
                    <pattern>
                        {
                          "service":     "${appName}",
                          "environment": "${environment}",
                          "version":     "${appVersion}"
                        }
                    </pattern>
                </pattern>
            </providers>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="JSON"/>
    </root>

</configuration>
```

What was removed vs current file:
- `<include resource="org/springframework/boot/logging/logback/defaults.xml"/>` — not needed with composite encoder
- `PatternLayoutEncoder` CONSOLE appender — replaced by JSON encoder
- `ROLLING_FILE` appender and its `<appender-ref>` — file appender violates LOG-INF-02
- `LOKI` (Loki4j) appender and its `<appender-ref>` — network appender violates LOG-INF-02
- `logLevel` and `logPattern` springProperty references — replaced by hard `level="INFO"` on root

Why `<mdc/>` satisfies LOG-INF-03: `micrometer-tracing-bridge-otel` (already in POM, already configured with `management.tracing.sampling.probability: 1.0`) automatically puts `traceId` and `spanId` into MDC on every traced request. The `<mdc/>` provider writes ALL MDC entries as top-level JSON fields. No additional code needed.
