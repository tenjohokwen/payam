Output: MtnMoMoClient has kv() log events in 7 public methods. OrangeMoneyClient has kv() log events in 7 public methods. All use System.currentTimeMillis() timing around makeHttpRequest() only.

Add these imports to MtnMoMoClient.java:
```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import static net.logstash.logback.argument.StructuredArguments.kv;
```

Add a logger field immediately after the class declaration:
```java
private static final Logger log = LoggerFactory.getLogger(MtnMoMoClient.class);
```

For each of the 7 public methods, add a `long start` timer immediately before `makeHttpRequest()` and a `log.info()` call immediately after `makeHttpRequest()` returns (before any null/status check that might throw).

The pattern for each method:
```java
long start = System.currentTimeMillis();
ResponseEntity<T> response = makeHttpRequest(...);
log.info("Provider HTTP call",
    kv("externalService", "MTN_MOMO"),
    kv("operation", "{methodName}"),
    kv("externalLatencyMs", System.currentTimeMillis() - start),
    kv("status", response.getStatusCode().is2xxSuccessful() ? "SUCCESS" : "FAILED"));
```

**fetchCollectionToken():** operation="fetchCollectionToken"
**fetchDisbursementToken():** operation="fetchDisbursementToken"
**requestToPay():** operation="requestToPay" — return type is `ResponseEntity<Void>`, status check is `response.getStatusCode().is2xxSuccessful()`
**getRequestToPayStatus():** operation="getRequestToPayStatus"
**validateAccountHolder():** operation="validateAccountHolder" — SPECIAL: this method has a try/catch for HttpClientException. Place `start` before `makeHttpRequest()` inside the `try` block, and the log call immediately after `makeHttpRequest()` returns (before the null check). The log will NOT emit on exception path — that is acceptable; the exception propagates for the not-found case.
**getBalance():** operation="getBalance"
**disburse():** operation="disburse" — return type is `ResponseEntity<Void>`

For methods returning `ResponseEntity<Void>` (requestToPay, disburse), use `response.getStatusCode().is2xxSuccessful()` as the status check.

Note on double-logging: RestRequestInterceptor already logs each HTTP call at INFO with raw method/url/status/latency strings. These LOG-BUS-06 events co-exist intentionally — the interceptor log is for debugging; the kv() event is for Loki querying. Add a brief comment in each method: `// LOG-BUS-06: structured latency event (co-exists with RestRequestInterceptor log)`.
