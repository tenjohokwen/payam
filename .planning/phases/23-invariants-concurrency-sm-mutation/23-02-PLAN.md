<objective>
Implement 4 concurrency tests (CONC-01 through CONC-04) in the `e2e/domain/` package.
Each uses standard Java concurrency primitives (CyclicBarrier, ExecutorService) to
create genuine race conditions against the running Spring application, then asserts
that invariants hold despite the races.

Purpose: Prove that the Redis NX+EX idempotency guard, state machine pessimistic locking,
Bucket4j velocity counters, and API key grace period all behave correctly under concurrent load.

threads and will destabilize Testcontainers if run in parallel with the plan-01 E2E tests.

**ConcurrentIdempotencyRaceTest** (CONC-01):
- Extends `AbstractPayamE2ETest` directly. Uses `@Autowired JdbcTemplate`, `TenantService`,
  `TenantRepository`.
- `@BeforeEach`: seed tenant, stub MTN initiation (GET accountholder 200, POST 202), seed
  fraud rules via `FraudVelocityBlockE2ETest.seedFraudRule()` pattern + `fraudRuleCache.refreshRules()`.
- Test: `twentyThreads_sameIdempotencyKey_producesExactlyOneRow()`:
  ```java
  int THREADS = 20;
  String sharedKey = UUID.randomUUID().toString();
  String msisdn = "+237672000001"; // MTN prefix
  CyclicBarrier barrier = new CyclicBarrier(THREADS);
  ExecutorService pool = Executors.newFixedThreadPool(THREADS);

  List<Future<ResponseEntity<PaymentResponse>>> futures = new ArrayList<>();
  for (int i = 0; i < THREADS; i++) {
      futures.add(pool.submit(() -> {
          try { barrier.await(10, TimeUnit.SECONDS); } catch (Exception ignored) {}
          return postPayment(sharedKey, msisdn);
      }));
  }
  pool.shutdown();
  assertThat(pool.awaitTermination(60, TimeUnit.SECONDS)).isTrue();
  ```
  Collect responses: for each future, call `f.get()` (wrap checked exceptions in
  RuntimeException). Collect all non-null `transactionId` values into a Set.
  Assert `txIds.size() == 1` — exactly one unique transactionId.
  Assert DB: `SELECT count(*) FROM main.transaction WHERE idempotency_key = ? AND tenant_id = ?`
  equals 1.
  Assert `mtnServer.verify(1, postRequestedFor(urlPathEqualTo("/v1_0/requesttopay")))`.

  Helper method `postPayment(String idempotencyKey, String msisdn)` returns
  `ResponseEntity<PaymentResponse>` using a `noRetryRestTemplate` (SimpleClientHttpRequestFactory
  + DefaultResponseErrorHandler returning false). Extract `serverPort` from AbstractPayamE2ETest.

  **Pitfall guard (from RESEARCH.md Pitfall 9):** Some threads may receive `null` transactionId
  (RESERVED state during in-flight processing). The assertion on `txIds` must use
  `.filter(Objects::nonNull)`. All non-null values must be the same. At least 1 non-null value
  must exist.

  **Pitfall guard (from RESEARCH.md Pitfall 2):** CyclicBarrier broken state on exception.
  Wrap `barrier.await()` in try-catch with `BrokenBarrierException` caught; use `f.get()`
  only after `pool.awaitTermination()` so exceptions surface as RuntimeException in the
  assertion phase, not during the concurrent submission phase.

**VelocityCounterFloodTest** (CONC-03):
- Extends `AbstractPayamE2ETest`. Uses `@Autowired JdbcTemplate`, `TransactionTemplate`,
  `FraudRuleCache`, `TenantService`, `TenantRepository`.
- Setup:
  - Seed tenant, stub MTN (GET accountholder 200, POST 202).
  - Set `IP_VELOCITY` threshold to 5 (low threshold for test speed). Set `BLOCK_THRESHOLD` to 35
    and `IP_VELOCITY` weight to 40 so 1 over-threshold IP request scores > 35 and gets blocked.
    Use the `FraudVelocityBlockE2ETest.seedFraudRule()` pattern + `fraudRuleCache.refreshRules()`.
    Use THRESHOLD = 5 consistently everywhere in this test — both in the seed SQL and in the
    Java constant `THRESHOLD = 5`.
  - Use a fixed source IP. Since the test HTTP client does not set `X-Forwarded-For` and the
    requests come from loopback, the fraud engine will see the same IP for all threads.

- Test: `hundredThreads_sameIp_atMostThresholdProviderCalls()`:
  ```java
  int THREADS = 100;
  int THRESHOLD = 5; // IP_VELOCITY threshold set in setup — matches seed SQL value
  CyclicBarrier barrier = new CyclicBarrier(THREADS);
  ExecutorService pool = Executors.newFixedThreadPool(THREADS);
  List<Future<ResponseEntity<PaymentResponse>>> futures = new ArrayList<>();
  for (int i = 0; i < THREADS; i++) {
      String uniqueKey = UUID.randomUUID().toString();
      futures.add(pool.submit(() -> {
          try { barrier.await(15, TimeUnit.SECONDS); } catch (Exception ignored) {}
          return postPayment(uniqueKey, "+237672000001");
      }));
  }
  pool.shutdown();
  assertThat(pool.awaitTermination(120, TimeUnit.SECONDS)).isTrue();
  ```

  Count outcomes:
  ```java
  long allowedCount = futures.stream()
      .map(f -> { try { return f.get(); } catch (Exception e) { throw new RuntimeException(e); } })
      .filter(r -> r.getStatusCode().value() == 202)
      .count();
  long blockedCount = futures.stream()
      .map(f -> { try { return f.get(); } catch (Exception e) { throw new RuntimeException(e); } })
      .filter(r -> r.getStatusCode().value() == 422)
      .count();
  ```

  Assert provider call count at most THRESHOLD:
  `mtnServer.verify(atMost(THRESHOLD), postRequestedFor(urlPathEqualTo("/v1_0/requesttopay")))`.
  Assert `allowedCount + blockedCount == THREADS`.
  Assert `blockedCount >= THREADS - THRESHOLD` (most are blocked).

  **Pitfall guard (RESEARCH.md Pitfall 4):** Do NOT assert Redis key value directly.
  `VelocityCheckService` uses Bucket4j CAS state blobs, not plain integer counters.
  Assert only the effect: provider call count ≤ threshold.

  Import `com.github.tomakehurst.wiremock.client.WireMock.atMost`.
